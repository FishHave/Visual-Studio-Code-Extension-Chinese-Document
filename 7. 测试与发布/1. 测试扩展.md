# 测试扩展
Visual Studio Code支持运行和调试测试您的扩展。这些测试再一个叫做**扩展开发宿主**的特别VS Code实例中运行，对VS Code API有完全访问权限。我们把这些测试叫做集成测试，因为他们不仅仅是不需要VS Code实例运行的单元测试。这份文档专注于VS Code的集成测试。

## 概览
如果您使用[Yeoman生成器](/2.%20开始/1.%20您的第一个扩展.md)构建了一个扩展，就已经创建了集成测试。

在生成的扩展中，使用`npm run test`或者`yarn test`运行集成测试：
- 下载并解压VS Code最新版本。
- 运行为扩展测试运行器脚本定制的[Mocha](https://mochajs.org/)。

## 快速开始：测试CLI
VS Code团队发布了一个命令行工具运行扩展测试。您可以在[扩展示例仓库](https://github.com/microsoft/vscode-extension-samples/tree/main/helloworld-test-cli-sample)找到示例。

测试CLI提供快速的入门，让您更容易使用[扩展测试运行器](https://marketplace.visualstudio.com/items?itemName=ms-vscode.extension-test-runner)运行并调试VS Code UI的测试。

您可以从安装`@vscode/test-cli`和`@vscode/test-electron`模块开始，这让您能够在VS Code桌面端运行测试：

```bash
npm install --save-dev @vscode/test-cli @vscode/test-electron
```
在安装完模块后，您就能在命令行中运行`vscode-test`，可以将其添加进`package.json`中的`scripts`字段：
```diff
{
    "name": "my-cool-extension",
    "scripts": {
        + "test": "vscode-test"
}
```

`vscode-test`将查找关联当前活动文件夹的[`.vscode-test.js/mjs/cjs`](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-cli-sample/.vscode-test.mjs)文件。这份文件提供了测试运行期的配置，您可以在[这](https://github.com/microsoft/vscode-test-cli/blob/main/src/config.cts)找到完整的定义。

通常的选项有：
- **（必需）**`files`，一个通配符、通配符列表或容纳要运行测试的绝对路径。
- `version` - 用于运行测试的VS Code版本（默认为`stable`）。
- `workspaceFolder` - 在测试中打开的工作空间路径。
- `extensionDevelopmentPath` - 您的扩展文件夹路径（默认为配置文件的文件夹）。
- `mocha` - 包含额外传递给Mocha的[选项](https://mochajs.org/api/mocha#Mocha)的对象。

配置文件可能如下一样简单：

```javascript
// .vscode-test.js
const { defineConfig } = require('@vscode/test-cli');

module.exports = defineConfig({ files: 'out/test/**/*.test.js' });
```

或更高级些：

```javascript
const { defineConfig } = require('@vscode/test-cli');

module.exports = defineConfig([
    {
        label: 'unitTests',
        files: 'out/test/**/*.test.js',
        version: 'insiders',
        workspaceFolder: './sampleWorkspace',
        mocha: {
            ui: 'tdd',
            timeout: 20000
        }
    }
    // 也可以指定其他测试配置
]);
```

如果您传递包含多个配置的数组，在运行`vscode-test`就会依次运行数组中的配置。您可以基于`label`筛选，并使用`--label`标记单独运行，例如`vscode-test --label unitTests`。运行`vscode-test --help`获得完整的命令行选项补全集合。

### 测试脚本
一旦启动了CLI，您可以编写并与逆行测试。测试脚本可以访问VS Code API，并在Mocha下运行。下面是示例（[src/test/suite/extension.test.ts](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/suite/extension.test.ts)）：

```typescript
import * as assert from 'assert';
// 您可以导入并使用所有来自'vscode'模块的API
// 也可以导入您自己的扩展测试
import * as vscode from 'vscode';
// import * as myExtension from '../extension';

suite('Extension Test Suite', () => {
    suiteTeardown(() => {
        vscode.window.showInformationMessage('All tests done!');
    });

    test('Sample test', () => {
        assert.strictEqual(-1, [1, 2, 3].indexOf(5));
        assert.strictEqual(-1, [1, 2, 3].indexOf(0));
    });
});
```

您可以使用`npm test`命令或在安装[扩展测试运行器](https://marketplace.visualstudio.com/items?itemName=ms-vscode.extension-test-runner)后使用VS Code **测试：运行所有测试**命令运行此测试。也可以使用**测试：调试所有测试**命令调试测试。

## 进阶开始：您自己的运行器

您可以在[helloworld-test-sample](https://github.com/microsoft/vscode-extension-samples/tree/main/helloworld-test-sample)中找到本指南的配置。文档的剩余部分解释示例上下文中的这些文件：
- **测试脚本**([`src/test/runTest.ts`](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/runTest.ts))
- **测试运行器脚本**([src/test/suite/index.ts](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/suite/index.ts))

VS Code为运行扩展测试提供了两个CLI参数：`--extensionDevelopmentPath`和`--extensionTestsPath`。

例如：
```bash
# - 启动VS Code扩展宿主
# - 加载位于<EXTENSION-ROOT-PATH>的扩展
# - 执行位于<TEST-RUNNER-SCRIPT-PATH>的测试运行器脚本
code \
--extensionDevelopmentPath=<EXTENSION-ROOT-PATH> \
--exensionTestsPath=<TEST-RUNNER-SCRIPT-PATH>
```

**测试脚本**([src/test/runTest.ts](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/runTest.ts))使用`@vscode/test-electron`API简化使用扩展测试参数下载、解压和启动VS Code的过程：

```typescript
import * as path from 'path';

import { runTests } from '@vscode/test-electron';

async function main() {
    try {
        // 把包括扩展清单package.json的文件夹
        // 传递`--extensionDevelopmentPath`
        const extensionDevelopmentPath = path.resolve(__dirname, '../../');

        // 把扩展测试运行器脚本的路径
        // 传递给--extensionTestsPath
        const extensionTestsPath = path.resolve(__dirname, './suite/index');

        // 下载并解压VS Code，运行集成测试
        await runTests({ extensionDevelopmentPath, extensionTestsPath });
    } catch (err) {
        console.error(err);
        console.error('Failed to run tests');
        process.exit(1);
    }
}

main();
```

`@vscode/test-electron`API允许：
- 使用指定工作空间启动VS Code
- 下载与最新稳定发布版本不同的VS Code版本
- 使用额外CLI参数启动VS Code

您可以在[microsoft/vscode-test](https://github.com/microsoft/vscode-test)找到更多API用法。

### 测试运行器脚本

在运行扩展集成测试时，`--extensionTestsPath`指向**测试运行器脚本**([`src/test/suite/index.ts`](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/suite/index.ts))，它通过编程运行测试套件。[测试运行器脚本](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/suite/index.ts)之下是`helloworld-test-sample`，它使用Mocha运行测试套件。您可以把这个当做起点，使用[Mocha API](https://mochajs.org/api/mocha)自定义您的启动。您也可以使用其他能够编程化运行的测试框架替代Mocha。

```typescript
import * as path from 'path';
import * as Mocha from 'mocha';
import { glob } from 'glob';

export function run(): Promise<void> {
    // 创建Mocha测试
    const mocha = new Mocha({
        ui: 'tdd',
        color: true
    });

    const testsRoot = path.resolve(__dirname, '..');

    return new Promise((c, e) => {
        glob('**/**.test.js', { cwd: testsRoot })
            .then(files => {
                // 向测试套件添加文件
                files.forEach(f => mocha.addFile(path.resolve(testsRoot, f)));

                try {
                    // 运行mocha测试
                    mocha.run(failures => {
                        if (failures > 0) {
                            e(new Error(`${failures} tests failed.`));
                        } else {
                            c();
                        }
                    });
                } catch (err) {
                    e(err);
                }
            })
            .catch(err => {
                return e(err);
            });
    });
}
```
运行测试运行器脚本，`*.test.js`文件能够访问VS Code API。

下面是示例测试（[src/test/suite/extension.test.ts](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/src/test/suite/extension.test.ts)）：

```typescript
import * as assert from 'assert';
import { after } from 'mocha';

// 您可以导入并使用所有来自'vscode'模块的API
// 也可以导入您自己的扩展测试
import * as vscode from 'vscode';
// import * as myExtension from '../extension';

suite('Extension Test Suite', () => {
  after(() => {
    vscode.window.showInformationMessage('All tests done!');
  });

  test('Sample test', () => {
    assert.strictEqual(-1, [1, 2, 3].indexOf(5));
    assert.strictEqual(-1, [1, 2, 3].indexOf(0));
  });
});
```

## 提示
### 使用内部版进行扩展开发
由于VS Code的限制，如果您正在使用VS Code稳定发布版尝试**在CLI**中运行集成测试，会抛出下面错误：

```text
Running extension tests from the command line is currently only supported if no other instance of Code is running.
```

通常来说，如果您在CLI运行扩展测试，测试正在运行的版本不能是已经在运行的。有一种替代方案是，您可以在VS Code稳定版中运行测试，并使用[VS Code内部版](https://code.visualstudio.com/insiders/)进行开发。只要您没有在VS Code内部版而是在VS Code稳定版运行测试，启动就会正常运作。

另一个方法是修改调试启动配置，在VS Code自身运行扩展测试。这个方法有一点好处就是您可以调试测试。

### 调试时禁用其他扩展

当您在VS Code中调试扩展测试时，VS Code使用全局安装的VS Code实例，并加载所有已安装的扩展。您可以在`launch.json`或`@vscode/test-electron`的`runTests`API的`launchArgs`选项中添加`--disable-extensions`配置。

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Extension Tests",
      "type": "extensionHost",
      "request": "launch",
      "runtimeExecutable": "${execPath}",
      "args": [
        "--disable-extensions",
        "--extensionDevelopmentPath=${workspaceFolder}",
        "--extensionTestsPath=${workspaceFolder}/out/test/suite/index"
      ],
      "outFiles": ["${workspaceFolder}/out/test/**/*.js"]
    }
  ]
}
```

```typescript
await runTests({
    extensionDevelopmentPath,
    extensionTestsPath,
    /**
     * 传递给VS Code可执行程序的启动参数列表，除了由`extensionDevelopmentPath`和`extensionTestsPath`选项提供的`--extensionDevelopmentPath`和`--extensionTestsPath`。
     * 
     * 如果第一个参数是文件、文件夹、工作空间的路径，启动的VS Code实例将打开它。
     * 
     * 参见`code --help`查看可能的参数
     */
    launchArgs: ['--disable-extensions']
});
```

### 使用@vscode/test-electron自定义安装

有些时候您想要运行自定义安装，比如运行`code --install-extension`在开始测试前安装另一个扩展。`@vscode/test-electron`拥有更细化的API以适应此场景：

```typescript
import * as cp from 'child_process';
import * as path from 'path';
import {
    downloadAndUnzipVS Code,
    resolveCliArgsFromVSCodeExecutablePath,
    runTests
} from '@vscode/test-electron';

async function main() {
    try {
        const extensionDevelopmentPath = path.resolve(__dirname, '../../../');
        const extensionTestsPath = path.resolve(__dirname, './suite/index');
        const vscodeExecutablePath = await downloadAndUnzipVSCode('1.40.1');
        const [cliPath, ...args] = resolveCliArgsFromVSCodeExecutablePath(vscodeExecutablePath);

        // 使用cp.spawn / cp.exec执行自定义安装
        cp.spawnSync(
            cliPath,
            [...args, '--install-extension', '<EXTENSION-ID-OR-PATH-TO-VSIX>'],
            {
                encoding: 'utf-8',
                stdio: 'inherit'
            }
        );

        // 运行扩展测试
        await runTests({
            // 使用指定`code`可执行程序
            vscodeExecutablePath,
            extensionDevelopmentPath,
            extensionTestsPath
        });
    } catch (err) {
        console.error('Failed to run tests');
        process.exit(1);
    }
}

main();
```

## 测试工作空间信任行为
如果您的扩展在`package.json`中声明了`capabilities.untrustedWorkspaces`，为信任和不信任的工作空间都添加集成测试，您不可以在扩展测试中编程化获取和撤销工作空间信任。为信任的和不信任的状态使用单独测试。

在使用`@vscode/test-cli`时，定义单独的测试配置，以便独立运行各个信任状态：

- **trustedWorkspaceTests**，给予您限制未生效的基准。这帮助您验证您的扩展的完全特性行为，并在信任的路径中捕捉回归。

- **untrustedWorkspaceTests**：验证工作空间信任启用时限制模式行为。使用专门的`--user-data-dir`避免之前保持的信任决定，防止本次运行意外被信任。

由于每个配置有各自的`label`，您可以单独运行（例如，`vscode-test --label trustedWorkspaceTests`和`vscode-test --label untrustedWorkspaceTests`）或者依次运行所有。

```javascript
// .vscode-test.js

const { defineConfig } = require('@vscode/test-cli');
const path = require('path');

module.exports = defineConfig([
    {
        label: 'trustedWorkspaceTests',
        files: 'out/test/**/*.test.js',
        workspaceFolder: './test/fixtures/trusted-workspace',
        //  可选：在本次运行禁用工作空间信任
        launchArgs: ['--disable-workspace-trust']
    },
    {
        label: 'untrustedWorkspaceTests',
        files: 'out/test/**/*.test.js',
        workspaceFolder: './test/fixtures/untrusted-workspace',
        // 保持开启工作空间信任，为确定的运行孤立用户数据
        launchArgs: [
            `--user-data-dir`,
            path.join(__dirname, 'vscode-test', 'user-data-untrusted')
        ]
    }
]);
```
在您的测试中，检查`vscode.workspace.isTrusted`断言信任感知行为：

```typescript
import * as assert from 'assert';
import * as vscode from 'vscode';

suite('Workspace Trust Tests', () => {
    test('extension behaviour changes by trust state', async () => {
        const isFeatureAvailable = await vscode.commands.executeCommand<boolean>(
            'myExtension.isRestrictedFeatureEnabled'
        );
        
        if (vscode.workspace.isTrusted) {
            assert.strictEqual(isFeatureAvailable, true);
        } else {
            assert.strictEqual(isFeatureAvailable, false);
        }
    });
});
```

关于更多如何在扩展清单中声明信任需求，以及如何使用`vscode.workspace.isTrusted`API的信息，参考[工作空间信任扩展指南](/4.%20扩展指南/14.%20工作空间信任.md)。

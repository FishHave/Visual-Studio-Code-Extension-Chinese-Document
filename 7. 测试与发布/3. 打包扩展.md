# 打包扩展

打包您的Visual Studio Code扩展的首要原因是确保任何平台的每个VS Code用户都能使用它。只有打包的扩展可以在[github.dev](https://github.dev/)和[vscode.dev](https://vscode.dev)等Web环境下运行。运行在浏览器中的VS Code只能加载一个存档文件，所以扩展文件需要打包为单个Web适配JavaScript文件。这也适用[笔记本输出渲染器](/4.%20扩展指南/9.%20笔记本.md#笔记本渲染器)，在这VS Code也只能为渲染器扩展加载一个文件。

另外，扩展的大小和复杂度可能高速增长。它们可能通过多个源文件编写，并依赖来自[npm](https://www.npmjs.com/)。分解和复用是开发中的最佳举措，然而它们却带有安装和运行的代价。加载100个小文件会比加载一个大文件慢很多。这就是为什么我们推荐打包。打包是将多个小源文件绑定为一个文件的过程。

## 使用esbuild
`esbuild`是易于配置的高速JavaScript打包器 。要获得esbuild，打开命令行解释器并输入：

```bash
npm i --save-dev esbuild
```

### 运行esbuild
您可以从命令行运行esbuild，但为了减少重复步骤，并启用问题报告，使用构建脚本`esbuild.js`更方便：

```javascript
const esbuild = require('esbuild');

const production = process.argv.includes('--production');
const watch = process.argv.includes('--watch');

async function main() {
    const ctx = await esbuild.context({
        entryPoints: ['src/extension.ts'],
        bundle: true,
        format: 'cjs',
        minify: production,
        sourcemap: !production,
        sourcesContent: false,
        platform: 'node',
        outfile: 'dist/extension.js',
        external: ['vscode'],
        logLevel: 'warning',
        plugins: [
            /* 添加到插件数组末尾 */
            esbuildProblemMatcherPlugin
        ]
    });
    if (watch) {
        await ctx.watch();
    } else {
        await ctx.rebuild();
        await ctx.dispose();
    }
}

/**
 * @type {import('esbuild').Plugin}
 */
const esbuildProblemMatcherPlugin = {
    name: 'esbuild-problem-matcher',

    setup(build) {
        build.onStart(() => {
            console.log('[watch] build started');
        });
        build.onEnd(result => {
            result.errors.forEach(({ text, location }) => {
                console.error(`✘ [ERROR] ${text}`);
                if (location == null) return;
                console.error(` ${location.file}:${location.line}:${location.column}:`);
            });
            console.log('[watch] build finished');
        });
    }
};

main().catch(e => {
    console.error(e);
    process.exit(1);
});
```

构建脚本的流程：
- 使用esbuild创建构建上下文。上下文配置为：
    - 将`src/extension.ts`的代码打包到单个文件`dist/extension.js`。
    - 如果传递了`--production`标记，压缩代码。
    - 除非传递了`--production`标记，生成源映射。
    - 从包体排除'vscode'模块（因为它由VS Code运行时提供）。
- 使用esbuildProblemMatcherPlugin插件报告组织打包器完成的错误。这个插件使用`esbuild`错误匹配器检测的格式发送错误，问题匹配器也应当作为扩展安装。
- 如果传递了`--watch`标记，它就会开始监视源文件的改动，并再检测到更改时重新构建包体。

esbuild可以直接操作TypeScript文件。然而，esbuild只会剔除所有的类型声明而不做类型检查。只会报告语法错误，可能导致esbuild构建失败。

出于此原因，我们单独运行TypeScript编译器（`tsc`）检查类型，但不产出任何代码（标记`--noEmit`）。

`package.json`中的`scripts`段现在如下：

```json
"scripts": {
    "compile": "npm run check-types && node esbuild.js",
    "check-types": "tsc --noEmit",
    "watch": "npm-run-all -p watch:*",
    "watch:esbuild": "node esbuild.js --watch",
    "watch:tsc": "tsc --noEmit --watch --project tsconfig.json",
    "vscode-prepublish": "npm run package",
    "package": "npm run check-types && node esbuild.js --production"
}
```

`npm-run-all`是并行运行匹配给定前缀脚本的node模块。对我们来说，它运行`watch:esbuild`和`watch:tsc`脚本。您只需添加`npm-run-all`到`package.json`的`devDependencies`段。

`compile`和`watch`脚本是提供给开发用的，它们会在产出包体时附带源映射。`package`脚本用于`vscode:prepublish`脚本，这个脚本又是由发布扩展前运行的`vsce`VS Code打包发布工具使用。向esbuild脚本传递`--production`标记将使其压缩代码，并创建较小的包体，但也会使得调试变得困难，所以开发中使用其他标记。要运行上面的脚本，打开命令行解释器，输入`npm run watch`或者从命令面板（<kbd>Ctrl+Shift+P</kbd>）选择**任务：运行任务**。
如果您用下面的方式配置`.vscode/tasks.json`，就会为每个监视任务开一个单独的命令行解释器。

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "watch",
      "dependsOn": ["npm: watch:tsc", "npm: watch:esbuild"],
      "presentation": {
        "reveal": "never"
      },
      "group": {
        "kind": "build",
        "isDefault": true
      }
    },
    {
      "type": "npm",
      "script": "watch:esbuild",
      "group": "build",
      "problemMatcher": "$esbuild-watch",
      "isBackground": true,
      "label": "npm: watch:esbuild",
      "presentation": {
        "group": "watch",
        "reveal": "never"
      }
    },
    {
      "type": "npm",
      "script": "watch:tsc",
      "group": "build",
      "problemMatcher": "$tsc-watch",
      "isBackground": true,
      "label": "npm: watch:tsc",
      "presentation": {
        "group": "watch",
        "reveal": "never"
      }
    }
  ]
}
```


这个监视任务依赖扩展[connor4312.esbuild-problem-matchers](https://marketplace.visualstudio.com/items?itemName=connor4312.esbuild-problem-matchers)提供问题匹配功能，您需要为此任务安装以在问题视图回报问题。完成启动需要安装此扩展。

为了防止忘记，向工作空间添加`.vscode/extensions.json`：
```json
{
    "recommendations": ["connor4312.esbuild-problem-matchers"]
}
```

最后，更新`.vscodeignore`文件，这样编译的文件就会被发布的扩展包含。查看[发布](2.%20发布扩展.md)获得更多详情。

跳转[测试](#测试)段落继续阅读。

## 使用webpack
Webpack是可以通过[npm](https://www.npmjs.com/)使用的开发工具。获取webpack和命令行界面，只需打开命令行解释器输入：

```bash
npm i --save-dev webpack webpack-cl
```

将安装webpack并更新扩展`package.json`文件，以在`devDependencies`中包含webpack。

webpack是JavaScript打包器，但许多VS Code扩展用TypeScript编写，并仅编译为JavaScript。如果您的扩展使用TypeScript，使用加载器`ts-loader`，这样webpack就能理解TypeScript。使用下方命令安装`ts-loader`：

```bash
npm i --save-dev ts-loader
```

所有文件可以在[webpack-extension](https://github.com/microsoft/vscode-extension-samples/blob/main/webpack-sample)示例找到。

### 配置webpack
所有工具已经安装，现在可以配置webpack。通常，指挥webpack打包扩展的配置存储在`webpack-config.js`文件中。下面的示例配置适用VS Code扩展，可以提供一个起点：

```javascript
//@ts-check

'use strict';

const path = require('path');
const webpack = require('webpack');

//**@type {import('webpack').Configuration}*/
const config = {
    target: 'webworker', // VS Code Web的扩展运行在webworker上下文中 📖 -> https://webpack.js.org/configuration/target/#target
    
    entry: './src/extension.ts', // 扩展入口点， 📖 -> https://webpack.js.org/configuration/entry-context/
    output: {
        // 包体存储在'dist'文件夹（检查package.json），📖 -> https://webpack.js.org/configuration/output/
        path: path.resolve(__dirname, 'dist'),
        filename: 'extension.js',
        libraryTarget: 'commonjs2',
        devtoolModuleFilenameTemplate: '../[resource-path]'
    },
    devtool: 'source-map',
    externals: {
        vscode: 'commonjs vscode' //VS Code模块在运行中创建，必须排除。添加其他不能被webpack打包的模块，📖 -> https://webpack.js.org/configuration/externals/
    },
    resolve: {
        // 支持读取TypeScript和JavaScript文件， 📖 -> https://github.com/TypeStrong/ts-loader
        mainFields: ['browser', 'module', 'main'], // 在导入的node模块中查找`browser`入口点
        extensions: ['.ts', '.js'],
        alias: {
            // 提供node模块和源文件的其他实现
        },
        fallback: {
            // webpack 5不再自动兼容Node.js核心模块。
            // 参考https://webpack.js.org/configuration/resolve/#resolvefallback
            // 查看Node.js核心模块兼容列表
        }
    },
    module: {
        rules: [
            {
                test: /\.ts$/,
                exclude: /node_modules/,
                use: [
                    {
                        loader: 'ts-loader'
                    }
                ]
            }
        ]
    }
};
module.exports = config;
```

文件可以在[webpack扩展](https://github.com/microsoft/vscode-extension-samples/blob/main/webpack-sample)示例中的部分[找到](https://github.com/microsoft/vscode-extension-samples/blob/main/webpack-sample/webpack.config.js)。webpack配置文件为普通的JavaScript模块，必须导入配置对象。

在上面的示例，定义了下面的内容：

- `target`指向扩展运行的上下文。我们推荐适用`webworker`以便扩展在VS Code Web和桌面版本使用。
- webpack应该使用的入口点。这类似于`package.json`中的`main`属性，只是您需要给webpack提供“source”入口点，通常为`src/extension.ts`，而且不包括“output”入口点。webpack打包器能理解TypeScript，所以无需单独的TypeScript编译步骤。
- `output`配置告知webpack需要在哪里放生成的打包文件。按照惯例是`dist`文件夹。在本例中，webpack会产出`dist/extension.js`文件。
- `resolve`和`module/rules`配置在此支持TypeScript和JavaScript输入文件。
- `externals`配置用于声明排除项，例如不需要包含在包体中的文件和模块。不应打包`vscode`模块，因为它不在磁盘上，而是在VS Code运行中需要时创建。基于扩展使用的node模块，可能需要更多的排除项。

最后，更新`.vscodeignore`文件，在发布的扩展中包含编译文件。检查[发布](2.%20发布扩展.md)小节获取更多细节。

### 运行webpack

`webpack.config.js`文件创建后，可以调用webpack。您可以从命令行运行webpack，但为了减少重复步骤，使用npm脚本会大有裨益。

将下面的项合并到`package.json`中的`scripts`段：

```json
"scripts": {
    "compile": "webpack --mode development",
    "watch": "webpack --mode development --watch",
    "vscode:prepublish": "npm run package",
    "package": "webpack --mode production --devtool hidden-source-map",
},
```

`compile`和`watch`脚本是提供给开发用的，它们会在产出包体时附带源映射。`package`脚本用于`vscode:prepublish`脚本，这个脚本又是由发布扩展前运行的`vsce`VS Code打包发布工具使用。[mode](https://webpack.js.org/concepts/mode/)的不同在于对优化程度的控制。使用`production`产出最小的包体，但花费更多时间，所以其他情况下使用`development`。要运行上方脚本，打开命令行解释器，输入`npm run compile`或者从命令面板（<kbd>Ctrl+Shift+P</kbd>）选择**任务：运行任务**。

## 运行扩展
在您可以运行扩展之前，`package.json`中的`main`属性必须指向包体，对于上方的配置来说是["./dist/extension"](https://github.com/microsoft/vscode-references-view/blob/d649d01d369e338bbe70c86e03f28269cbf87027/package.json#L26)。这么修改后，扩展现在可以执行和测试。

## 测试
扩展作者通常为扩展源代码编写单元测试。正确的结构层次下，扩展源代码不依赖测试，webpack和esbuild包体不应该包含任何测试代码。如需运行单元测试，只有简单的编译是需要的。

将下面的项目合并入`package.json`的`scripts`段：

```json
"scripts": {
    "compile-test": "tsc -p, --outDir out",
    "pretest": "npm run compile-tests",
    "test": "vscode-test"
}
```

`compile-tests`脚本使用TypeScript编译器编译扩展到`out`文件夹。就有了可用的中间JavaScript代码，下面`launch.json`的脚本片段足够用来运行测试：

```json
{
    "name": "Extension Tests",
    "type": "extensionHost",
    "request": "launch",
    "runtimeExecutable": "${execPath}",
    "args": [
        "--extensionDevelopmentPath=${workspaceFolder}",
        "--extensionTestsPath=${workspaceFolder}/out/test"
    ],
    "outFiles": ["${workspaceFolder}/out/test/**/*.js"],
    "preLaunchTask": "npm: compile-tests"
}
```
下面对于运行测试的配置与非打包扩展一致。没有必要打包单元测试，因为它们并不是扩展发布的一部分。

## 发布

在发布前，应当更新`.vscodeignore`文件。一切打包到`dist/extension.js`中的文件可以排除，通常为`out`文件夹（以防您不能删除它）和最重要的`node_modules`文件夹。

常见的`.vscodeignore`文件看起来如下：

```bash
.vscode
node_modules
out/
src/
tsconfig.json
webpack.config.js
esbuild.js
```

- 享受安装加载更加快速的扩展！

## 疑难解答

### 最小化
`production`模式下的打包同样让代码最小化。最小化通过移除空格和注释并让变量和函数名变得丑陋但简短来简化源代码。使用`Function.prototype.name`的源代码有不同的运作方式，所以您可能需要禁用最小化。

### webpack关键依赖
在运行webpack时，您可能会遇到**Critical dependencies: the request of a dependency is an expression.**类似的警告。这样的警告必须慎重对待，很可能您的打包不会运作。这条消息意思是webpack不能静态决定如何打包某些依赖。这通常由动态`require`语句导致，例如`require(someDynamicVariable)`。

为了解决此警告，选择其一实施：

- 尝试使用可以打包的静态依赖。
- 通过`external`配置排除依赖。确保那些JavaScript文件不会被打包的扩展排除，在`.vscodeignore`中使用反[全局通配符](https://code.visualstudio.com/docs/editor/glob-patterns)，例如：`!node_modules/mySpecialModule`。

# 发布扩展

当您完成了一个高质量扩展后，您可以将其发布至[VS Code扩展市场](https://marketplace.visualstudio.com/vscode)，这样其他人就能找到、下载并使用您的扩展。另外，您可以[打包](#打包扩展)为可安装VSIX格式并分享给其他用户。

本主题包含：
- 使用[vsce](#vsce)这个CLI工具管理VS Code扩展
- [打包](#打包扩展)、[发布](#发布扩展)并[撤回](#撤回扩展)扩展
- 必要时[注册发布者](#创建发布者)方便发布扩展

## vsce
[vsce](https://github.com/microsoft/vscode-vsce)，全称Visual Studio Code Extension（Visual Studio Code扩展），是打包、发布、管理VS Code扩展的命令行工具。


### 安装

确保您已经安装了[Node.js](https://nodejs.org/)。并运行：
```bash
npm install -g @vscode/vsce
```

### 用法

您可以使用`vsce`便捷地[打包](#打包扩展)并[发布](#发布扩展)您的扩展：

```bash
$ cd myExtension
$ vsce package
# myExtension.vsix generated
$ vsce publish
# <publisher id>.myExtension published to VS Code Marketplace
```

`vsce`也可以搜索检索元数据，并撤回扩展。运行`vsce --help`查阅所有可用的`vsce`命令。

## 发布扩展
> 注意
> 由于安全问题，`vsce`不会发布包含用户提供SVG图像的扩展。

发布工具检查下面的限制：

- `package.json`提供的图标不应该是SVG。
- `package.json`提供的标志不应该是SVG图像，除非来自[信任的标志提供者](#允许的标志提供者)。
- `README.md`和`CHANGELOG.md`的图像URL应该解析为`https`URL。
- `README.md`和`CHANGELOG.md`的图像不应该是SVG，除非来自[信任的标志提供者](#允许的标志提供者)。

Visual Studio Code使用[Azure DevOps](https://azure.microsoft.com/zh-cn/products/devops/)提供市场服务。这意味着扩展的授权、托管和管理都由Azure DevOps提供。

> 重要事项
> 在2026年12月1日，Azure DevOps全球个人访问令牌（PATs）停用。为了继续发布扩展，使用Microsoft Entra ID代替，以[保证安全自动化发布](#安全自动化发布到Visual Studio Code市场)。想要更多信息，参见[Azure DevOps全球个人令牌停用](https://devblogs.microsoft.com/devops/retirement-of-global-personal-access-tokens-in-azure-devops/)

### 安全自动化发布到Visual Studio Code市场
我们推荐扩展使用[基于Microsoft Entra ID授权](https://learn.microsoft.com/en-us/azure/devops/integrate/get-started/authentication/entra?view=azure-devops)和**工作负载身份联合与托管标识**发布扩展。这个方法消除了消除了如个人访问令牌（PATs）的隐秘，并确保安全、自动化的发布管线。

这个方法通过避免对存储证书的依赖增强了全面安全姿态，通过本地整合Azure管线和Entra ID简化操作，高效跨越多个环境，并适配企业级别的国际认证和访问管理标准。想要更多信息，参见[减少PAT使用](https://devblogs.microsoft.com/devops/reducing-pat-usage-across-azure-devops/)。

1. 创建服务连接（Azure DeveOps）
    - 导航到**Project Settings** → **Service Connections**
    - 创建新的**Azure Resource Manager**连接
    - 选择**Workload Identity Federation (manual)**
    - 在草稿模式下保存连接，之后收集需要的值
2. 创建托管认证（Azure）
    - 在Azure创建**user-assigned managed identity**
    - 指定**Reader**角色
    - 记录下面的值：**Client ID**、**Tenant ID**、**Subscription**详情。
3. 配置联合证书
    建立Azure DevOps和Azure之间的连接：
        - 为托管认证添加联合证书
        - 在两个系统之间交换需要的值：
            - 从Azure DevOps → Azure：**Issuer and subject**
            - 从Azure → Azure DevOps：**client ID, tenant ID, subscription**
        - 在Azure DevOps，选择**Verify and save**
4. 获得管线访问
    - 打开服务连接
    - 获得负责发布的管线访问
5. 检索托管认证资源ID（一次）
    - 运行Azure CLI任务检索认证信息：
```yaml
steps:
- task: AzureCLI@2
  displayName: 'Get identity details'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      az rest -u https://app.vssps.visualstudio.com/_apis/profile/profiles/me --resource 499b84ac-1321-427f-aa17-267ca6975798

```
    - 从输出的JSON，捕获托管认证资源ID（`id`字段）。
6. 授权Visual Studio市场认证
    - 添加托管认证（使用其资源ID）作为发布者的成员
    - 指定**Contributor**角色
7. 配置CI/CD管线
    - 创建Azure管线CI/CD工作流
    - 用基于认证的方式取代基于PAT授权
8. 使用托管认证发布
    - 在您的管线，通过Azure CLI生成Microsoft Entra ID(AAD)访问令牌。 
    - 在您的发布命令中使用令牌（例如：`vsce publish --azure-credential`）。
示例YAML任务。用扩展文件夹路径填入。

```YAML
# 安装VS Code扩展管理器（需要v2.26.1以上的vsce）和依赖
- script: |
    cd <ExtensionDirectory>
    npm install -g @vscode/vsce
    npm install
  displayName: "Install vsce and dependencies"

# 发布
- task: AzureCLI@2
  displayName: 'Publish using managed identity'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      cd <ExtensionDirectory>
      vsce publish --azure-credential

```

`vsce`也可以使用[个人访问令牌](https://learn.microsoft.com/zh-cn/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate?view=azure-devops)发布扩展。

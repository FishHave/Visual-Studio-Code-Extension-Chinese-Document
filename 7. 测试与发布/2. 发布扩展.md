# 发布扩展

当您完成了一个高质量扩展后，您可以将其发布至[VS Code扩展市场](https://marketplace.visualstudio.com/vscode)，这样其他人就能找到、下载并使用您的扩展。另外，您可以[打包](#打包扩展)为可安装VSIX格式并分享给其他用户。

本主题包含：
- 使用[vsce](#vsce)这个CLI工具管理VS Code扩展
- [打包](#打包扩展)、[发布](#发布扩展)并[撤回](#撤回扩展)扩展
- 必要时[注册发布者](#创建发布者)方便发布扩展

## vsce
[vsce](https://github.com/microsoft/vscode-vsce)，全称Visual Studio Code Extension（Visual Studio Code扩展），是打包、发布、管理VS Code扩展的命令行工具。


### 安装

确保您已经安装了[Node.js](https://nodejs.org/)。并运行：
```bash
npm install -g @vscode/vsce
```

### 用法

您可以使用`vsce`便捷地[打包](#打包扩展)并[发布](#发布扩展)您的扩展：

```bash
$ cd myExtension
$ vsce package
# myExtension.vsix generated
$ vsce publish
# <publisher id>.myExtension published to VS Code Marketplace
```

`vsce`也可以搜索检索元数据，并撤回扩展。运行`vsce --help`查阅所有可用的`vsce`命令。

## 发布扩展
> 注意
> 由于安全问题，`vsce`不会发布包含用户提供SVG图像的扩展。

发布工具检查下面的限制：

- `package.json`提供的图标不应该是SVG。
- `package.json`提供的标志不应该是SVG图像，除非来自[信任的标志提供者](#允许的标志提供者)。
- `README.md`和`CHANGELOG.md`的图像URL应该解析为`https`URL。
- `README.md`和`CHANGELOG.md`的图像不应该是SVG，除非来自[信任的标志提供者](#允许的标志提供者)。

Visual Studio Code使用[Azure DevOps](https://azure.microsoft.com/zh-cn/products/devops/)提供市场服务。这意味着扩展的授权、托管和管理都由Azure DevOps提供。

> 重要事项
> 在2026年12月1日，Azure DevOps全球个人访问令牌（PATs）停用。为了继续发布扩展，使用Microsoft Entra ID代替，以[保证安全自动化发布](#安全自动化发布到Visual Studio Code市场)。想要更多信息，参见[Azure DevOps全球个人令牌停用](https://devblogs.microsoft.com/devops/retirement-of-global-personal-access-tokens-in-azure-devops/)

### 安全自动化发布到Visual Studio Code市场
我们推荐扩展使用[基于Microsoft Entra ID授权](https://learn.microsoft.com/en-us/azure/devops/integrate/get-started/authentication/entra?view=azure-devops)和**工作负载身份联合与托管标识**发布扩展。这个方法消除了消除了如个人访问令牌（PATs）的隐秘，并确保安全、自动化的发布管线。

这个方法通过避免对存储证书的依赖增强了全面安全姿态，通过本地整合Azure管线和Entra ID简化操作，高效跨越多个环境，并适配企业级别的国际认证和访问管理标准。想要更多信息，参见[减少PAT使用](https://devblogs.microsoft.com/devops/reducing-pat-usage-across-azure-devops/)。

1. 创建服务连接（Azure DeveOps）
    - 导航到**Project Settings** → **Service Connections**
    - 创建新的**Azure Resource Manager**连接
    - 选择**Workload Identity Federation (manual)**
    - 在草稿模式下保存连接，之后收集需要的值
2. 创建托管认证（Azure）
    - 在Azure创建**user-assigned managed identity**
    - 指定**Reader**角色
    - 记录下面的值：**Client ID**、**Tenant ID**、**Subscription**详情。
3. 配置联合证书
    建立Azure DevOps和Azure之间的连接：
        - 为托管认证添加联合证书
        - 在两个系统之间交换需要的值：
            - 从Azure DevOps → Azure：**Issuer and subject**
            - 从Azure → Azure DevOps：**client ID, tenant ID, subscription**
        - 在Azure DevOps，选择**Verify and save**
4. 获得管线访问
    - 打开服务连接
    - 获得负责发布的管线访问
5. 检索托管认证资源ID（一次）
    - 运行Azure CLI任务检索认证信息：
```yaml
steps:
- task: AzureCLI@2
  displayName: 'Get identity details'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      az rest -u https://app.vssps.visualstudio.com/_apis/profile/profiles/me --resource 499b84ac-1321-427f-aa17-267ca6975798

```
    - 从输出的JSON，捕获托管认证资源ID（`id`字段）。
6. 授权Visual Studio市场认证
    - 添加托管认证（使用其资源ID）作为发布者的成员
    - 指定**Contributor**角色
7. 配置CI/CD管线
    - 创建Azure管线CI/CD工作流
    - 用基于认证的方式取代基于PAT授权
8. 使用托管认证发布
    - 在您的管线，通过Azure CLI生成Microsoft Entra ID(AAD)访问令牌。 
    - 在您的发布命令中使用令牌（例如：`vsce publish --azure-credential`）。
示例YAML任务。用扩展文件夹路径填入。

```YAML
# 安装VS Code扩展管理器（需要v2.26.1以上的vsce）和依赖
- script: |
    cd <ExtensionDirectory>
    npm install -g @vscode/vsce
    npm install
  displayName: "Install vsce and dependencies"

# 发布
- task: AzureCLI@2
  displayName: 'Publish using managed identity'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      cd <ExtensionDirectory>
      vsce publish --azure-credential

```

`vsce`也可以使用[个人访问令牌](https://learn.microsoft.com/zh-cn/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate?view=azure-devops)发布扩展。

> 重要事项
> 在2026年12月1日，Azure DevOps全球个人访问令牌（PATs）停用。为了继续发布扩展，使用Microsoft Entra ID代替，以[保证安全自动化发布](#安全自动化发布到Visual Studio Code市场)。想要更多信息，参见[Azure DevOps全球个人令牌停用](https://devblogs.microsoft.com/devops/retirement-of-global-personal-access-tokens-in-azure-devops/)

### 获得个人访问令牌

您可以通过Azure DevOps门户创建个人访问令牌。如需创建个人访问令牌：

1. 如果您还没有Azure DevOps组织。跟随[创建组织](https://learn.microsoft.com/azure/devops/organizations/accounts/create-organization)一文的步骤。

2. 转到[Azure DevOps门户](https://go.microsoft.com/fwlink/?LinkId=307137)，选择您的组织。

3. 打开档案图像旁的用户设置下拉框，选择**Personal access tokens**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/menu-pat.png)

4. 在**Personal Access Tokens**页面，选择**New Token**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/new-token.png)

5. 在创建新的个人访问令牌对话框，填写下面令牌详情：

    - Name：您为令牌随意取的名称
    - Organization：**All accessible organizations**
    - Expiration（可选）：设置令牌期望的到期时间
    - Scopes：**Custom defined**：
        - 点击**Scopes**段下面的**Show all scopes**链接
        - 在Scopes列表，滑到**Marketplace**选择**Manage**领域

6. 点击**Create**

您就能看到您新创建的个人访问令牌。**拷贝**到安全的位置，随后就需要[创建发布者](#创建发布者)

### 创建发布者

**发布者**是可以发布扩展到Visual Studio Code市场的认证。每个扩展需要在[`package.json`文件](/9.%20参考/4.%20扩展清单.md)包含一个`publisher`标识符。

如需创建发布者：
1. 转到[Visual Studio市场发布者管理页面](https://marketplace.visualstudio.com/manage)。

2. 登录您在之前小节用于创建[个人访问令牌](#获得个人访问令牌)的Microsoft账户。

3. 在左边的面板点击**Create publisher**

4. 在新的页面，指定新发布者的必需参数——标识符和名称（分别为**ID**和**Name**输入框）：
    - **ID**：您在市场中发布者的**唯一**标识符，用在您的扩展URL当中。ID一旦创建不可更改。
    - **Name**：您的发布者的**唯一**名称，将在市场中与扩展一同显示。这可以是您的公司或品牌名称。

下面是Python扩展发布者标识符和名称的例子：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/publisher-id-and-name.png)

5. 可以选择填写剩下的输入框。

6. 点击**Create**

7. 使用`vsce`验证新创建的发布者。在终端中运行下面的命令，有提示词出现时，输入前面步骤创建的个人访问令牌：

```bash
vsce login <publisher id>

https://marketplace.visualstudio.com/manage/publishers/
Personal Access Token for publisher '<publisher id>': ****************************************************

The Personal Access Token verification succeeded for the publisher '<publisher id>'.
```

完成验证后，您可以发布扩展了。

### 发布扩展

您可以用两种方式发布扩展：

1. 使用`vsce publish`命令自动发布扩展：


```bash
vsce publish
```

如果您在上面还没有用`vsce login`命令提供您的个人访问令牌，`vsce`会要求您提供。

2. 使用`vsce package`打包扩展为可安装VSIX格式，随后手动上传到[Visual Studio市场发布者管理页面](https://marketplace.visualstudio.com/manage)

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/extension-report.png)

## 自动迭代扩展版本
发布完扩展后，您可以指定遵循[语义化版本](https://semver.org/)的数值或版本符号（`major`、`minor`或`patch`）来递增其版本数。例如，要把1.0.0扩展更新为1.1.0，您可以指定：

```bash
vsce publish minor
```
或
```bash
vsce publish 1.1.0
```

两个命令都会首先修改扩展`package.json`[version](/9.%20参考/4.%20扩展清单.md)属性，随后发布更新后的版本。

> 提示
> 如果在git仓库中您运行了`vsce publish`，它也会创建版本提交，并通过[npm-version](https://docs.npmjs.com/cli/version#description)打上标签。默认提交信息为扩展的版本，但您可以使用`-m`标记提供自定义提交消息（在提交消息中可以用`%s`引用当前的版本）。

## 撤回扩展
您可以在[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)撤回扩展，点击**Actions -> Unpublish**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/unpublish-extension.png)

撤回后，扩展的可用状态更改为**Unpublished**，它将不再可以从市场和Visual Studio Code下载。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/unpublished-extension.png)

> 注意
> 当您撤回扩展时，市场保留扩展统计。扩展可以被公众找到，并对已有的API可用。

## 移除扩展
您可以用两种方式移除扩展：

1. 使用[`vsce`](#vsce)的`unpublish`命令自动移除：

```bash
vsce unpublish <publisher id>.<extension name>
```

2. 在[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)点击**More Actions > Remove**手动移除：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/remove-extension.png)

两种情况下，会提示您通过输入扩展名称确认移除。注意移除操作是**不可逆的**。

> 提示
> 当您移除扩展时，市场也会移除扩展的所有统计。您可能更应该撤回扩展而不是移除之。重要的是！扩展名称是在Visual Studio Code市场中的唯一标识符。一旦扩展移除，它的扩展将永久保留且不能复用，甚至是其原发布者。这对保护用户免遭高仿，并维护市场生态系统的信用大有帮助。在删除扩展前，确保您不再需要这个名称，因为这个操作是不可逆的。

## 移除指定扩展版本
您可以在[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)选择**More Actions > Reports**移除指定扩展版本：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/extension-manage.png)

在**Manage**栏，选择**Delete this version**。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/remove-version.png)

您会收到提示通过输入扩展名称确认移除。这个操作是**不可逆的**。

> 重要事项
> 删除后，您不能在新的发布中复用此版本数字。另外，您不能删除扩展的最新版本。

## 打包扩展

如果您想要做下列事情，可以选择打包扩展：

- 在VS Code实例中测试扩展。
- 不发布到市场进行分发。
- 私下分享给其他人。

打包意味着创建一个包含扩展的`.vsix`文件。这个文件可以在VS Code中安装。一些扩展在GitHub发布中发布`.vsix`文件。

要打包扩展，在扩展根目录下运行下面的命令：

```bash
vsce package
```

这个命令在扩展根目录创建`.vsix`文件。例如`my-extension-0.0.1.vsix`。

对于用户，要在VS Code中安装`.vsix`文件：
    - 在VS Code扩展视图
        1. 转到扩展视图。
        2. 选择**Views and More Actions...**
        3. 选择**Install from VSIX...**
    - 从命令行：
```bash
# 如果您使用VS Code
code --install-extension my-extension-0.0.1.vsix

# 如果您使用VS Code内部版
code-insiders --install-extension my-extension-0.0.1.vsix
```

## 您的扩展文件夹

要加载扩展，您需要拷贝文件到VS Code扩展文件夹`.vscode/extension`。基于您的操作系统，文件夹有不同的位置：
- **Windows:** `%USERPROFILE%\.vscode\extensions`
- **macOS:** `~/.vscode/extensions`
- **Linux:** `~/.vscode/extensions`

## Visual Studio Code适配

创建扩展时，您必须指定扩展适配的VS Code。方法是在`package.json`中使用`engines.vscode`属性：

```json
{
    "engines": {
        "vscode": "^1.8.0"
    }
}
```
- 值`1.8.0`（没有脱字符号）意思是扩展仅适配VS Code `1.8.0`
- 值`^1.8.0`意思是您的扩展适配VS Code `1.8.0`以上，包括`1.8.1`、`1.9.0`等等。

您可以使用`engines.vscode`属性确保扩展仅在包含依赖的API客户端上安装。这个机制能在稳定版和内部版发布正常工作。

例如，VS Code最新稳定版本是`1.8.0`。在`1.9.0`版本开发中，引入了新的API，并在`1.9.0-insider`版本内部版发布中可用。如果您想要发布利用此API的扩展，您应当指定版本依赖为`^1.9.0`。这样，您的新扩展版本将仅在VS Code`>=1.9.0`（换句话说，当前内部版发布的用户）可用。VS Code稳定版用户将仅在稳定版发布`1.9.0`版本时更新。

如要面向根据日期构建的内部版，在版本中增加`YYYYMMDD`格式的日期标签。VS Code 1.57之后强制日期标签。早期版本仅评估版本的数字部分。例如，`^1.56.0-20210428`面向VS Code 1.56之后，2021年4月28日0:00 UTC之后的构建。

## 进阶用法
### 市场集成

您可以自定义扩展在Visual Studio市场中的样子。以[Go Extension](https://marketplace.visualstudio.com/items?itemName=golang.go)为例。

下面是让您的扩展在市场上出类拔萃的提示：

- 在扩展根目录下添加`README.md`文件，写入您想要在扩展市场页面显示的内容。

> 提示
> 如果您的`package.json`中存在`repository`属性指向公开GitHub仓库，`vsce`将自动检测，并相应地调整相对链接，默认使用`main`分支。您可以在运行`vsce package`或`vsce publish`时，使用`--githubBranch`标记覆盖。也可以使用`--baseContentUrl`和`--baseImageUrl`标记，为链接和图像设置基础URL。

- 在扩展根目录添加`LICENSE`文件，写入扩展协议信息。

- 在扩展根目录添加`CHANGELOG.md`文件，写入扩展更改历史信息。

- 在扩展根目录下添加`SUPPORT.md`文件，写入如何获得扩展支持的信息。

- 通过指定`package.json`中的`galleryBanner.color`属性为相应的十六进制值，设置市场页面的旗帜背景颜色。

- 通过在`package.json`中指定`icon`属性为扩展中的一个至少为128x128px PNG文件相对路径，设置图标。

更多信息见[市场呈现提示](/9.%20参考/4.%20扩展清单.md#市场呈现提示)。

### 验证发布者

您可以验证您的品牌或标识符相关的[合格域名](#合格域名)拥有者，并成为经过验证的发布者。如果您的发布者经过验证，市场会向您的扩展细节添加验证标记。

### 准备
验证的发布者必须在VS市场持有一个以上的扩展达到6个月，域名的注册必须达到6个月。在验证前，请等待直到符合条件。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/verified-publisher.png)

验证发布者：

1. 转到[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)。

2. 在左边的面板，选择或[创建](#创建发布者)您希望验证的发布者。

3. 在主面板，选择**Details**栏。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/publisher-details-tab.png)

4. 在**Details栏**，**Verified domain**部分下方，输入一个[合格域名](#合格域名)。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/publisher-details-tab-verified-domain.png)

> **注意**：注意到您可以输入后**Details**标题旁边有个星号（*）。就像在VS Code一样，这代表您有为保存的更改。出于相同的原因，**Verify**按钮被禁用。

5. 选择**Save**，然后选择**Verify**。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/saved-domain-to-verify.png)

将出现一个对话框，告知您添加域名DNS配置的TXT记录。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/txt-record-verification.png)

6. 跟随说明，为域名DNS配置添加TXT记录。

7. 在对话框中选择**Verify**，校验成功添加的TXT记录。

### 合格域名

合格域名满足下列条件：

- 您必须能够管理DNS配置设置，并添加TXT记录。
- 这不是子域名（{子域名}.github.io、{子域名}.contoso.com或其他类似情况）。
- 必须使用HTTP协议。
- 必须能够对头请求恢复HTTP 200状态。

### 扩展定价标签
您可以选择为扩展市场页面加入定价标签，表明其为`Free`（免费）或`Free Trial`（免费试用）。

要添加定价标签，在`package.json`中添加`pricing`属性。比如：

```json
{
    "pricing": "Free"
}
```

允许的值有：`Free`和`Trial`（大小写敏感）。当`pricing`属性未指定时，默认值为`Free`。

> 注意
> 在发布时如果想要扩展的定价标签正常运作，请确保`vsce`版本高于`2.10.0`。

### 扩展赞助

您可以选择加入赞助，让用户了解支持工作的方式。

如要显示赞助链接，向`package.json`添加`sponsor`属性。例如：

```json
"sponsor": {
    "url": "https://github.com/sponsers/nvaccess"
}
```

> 注意
> 在发布时如果想要扩展的赞助标签正常运作，请确保`vsce`版本高于`2.9.1`。

赞助链接会出现在市场和VS Code扩展详情页面顶部：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/sponsor-link-example.png)

我们希望这让用户自主他们依赖的扩展以帮助改进扩展性能、可靠性与稳定性。

### 使用.vscodeignore

您可以创建`.vscodeignore`文件避免一些文件被包含进入扩展包体。这个文件是[路径](https://github.com/isaacs/minimatch)通配模式，每个一行。例如：

```bash
**/*.ts
**/tsconfig.json
!file.ts
```

您应该忽略在运行时非必需的文件。例如，如果您的扩展使用TypeScript编写，您应该忽略所有的`**/*.ts`文件，如上方的示例。

> 注意
> 在`devDependencies`中列出的开发依赖会被自动忽略，所以您不需要单独加入。

### 预发布步骤

您可以在清单文件中添加预发布步骤，在每次扩展打包时调用。例如，您在这个阶段可能想要调用[TypeScript](https://www.typescriptlang.org/)编译器：

```json
        "vscode": "0.10.x"

    }

```

### 预览扩展

用户可以在VS Code或VS Code内部版安装扩展预览版本，定期在官方扩展发布前获取最新扩展版本。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/pre-release.png)

要发布预览版本，向`vsce package`或`vsce publish`命令传递`--pre-release`标记：

```bash
vsce package --pre-release
vsce package --pre-release
```

对于扩展版本，我们仅支持`主版本号.次版本号.补丁号`，预览标签`semver`**不受支持**。预览和常规版本的版本号必须不同。也就是说，如果预览版本上传了`1.2.3`，下次常规版本必须上传不同的版本号，比如`1.2.4`。未来将支持完整的语义化版本。

VS Code会自动上传扩展为最高可用版本，所以即使用户选择预览版本，而扩展有更高版本，用户会更新为发布的版本。所以，所以，我们推荐扩展为发布版本使用`主版本号.偶数.补丁号`，为预览版本使用`主版本号.奇数.补丁号`。例如，发布版本`0.2.*`，预览版本`0.3.*`。

如果扩展作者不想要预览用户更新为发布版本，我们推荐永远在发布发布版本前迭代并发布新的预览版本，以确保预览版本永远较高。注意预览用户在发布版本较高时将更新为发布版本，但是他们仍然可以自动更新为未来更高的预览版本。

VS Code自`1.63.0`后支持预览扩展，所以预览扩展应该让`package.json`的`engines.vscode`值大于`1.63.0`。

> 注意
> 已经有独立的预览版本扩展应当联系VS Code团队，为过时的独立扩展启用自动卸载和安装主扩展的预览版本。

### 平台独占扩展
您可以为每个平台运行的VS Code发布扩展的VSIX包（Windows、Linux、macOS）。我们叫这种扩展**平台独占**。

从`1.61.0`版本开始，VS Code查找匹配当前平台的扩展包。

如果扩展有平台独占的库或依赖，平台独占扩展就起了作用，这样您可以控制被某个平台包包含的实际二进制文件。常见用法是**本地Node模块**。

平台独占扩展作为独立的包发布，包含平台独占内容。您可以通过传递[`--target`标记](#发布)指定目标平台。如果您不传递这个标记，包会用于所有没有平台独占包的平台的回退。

当前可用的平台有：`win32-x64`、`win32-arm64`、`linux-x64`、`linux-arm64`、`linux-armhf`、`alpine-x64`、`alpine-arm64`、`darwin-x64`、`darwin-arm64`与`web`。

如果您想要平台独占扩展同样支持浏览器以成为[Web扩展](/4.%20扩展指南/13.%20Web扩展.md)，它**必须**在发布时面向`web`平台。`web`平台期望`package.json`中的`browser`入口。如要禁用不支持`web`的扩展功能，我们推荐在`package.json`中使用时词，而不是为Web平台搭载独立的`package.json`或者移除不在`web`上工作的VSIX部件。

#### 发布

从`1.99.0`起，[vsce](https://github.com/microsoft/vscode-vsce)支持`--target`参数在打包并发布VSIX时指定目标平台。

下面是为`win32-x64`和`win32-arm64`平台发布VSIX的方法：

```bash
vsce publish --target win32-x64 win32-arm64
```

您也可以在打包并创建平台独占VSIX时使用`--target`标记。例如，要为`win32-x64`平台打包VSIX并发布时：

```bash
vsce package --target win32-x64
vsce publish --packagePath PATH_TO_WIN32_X64_VSIX
```

#### 持续集成

管理多个平台独占VSIX可能有些让人不知所措，所以我们建议使用[持续集成](4.%20持续集成.md)（CI）工具自动化您的扩展构建进程。例如，您可以使用[GitHub Actions](https://github.com/features/actions)构建您的扩展。我们的[平台独占扩展示例](https://github.com/microsoft/vscode-platform-specific-sample)可以作为学习的切入点：它的[工作流](https://github.com/microsoft/vscode-platform-specific-sample/blob/main/.github/workflows/ci.yml)适用适用平台独占扩展的常见场景，并支持在所有受支持的VS Code目标分发作为依赖的本地Node模块。

## 常见问题
### 在发布扩展时报错“You exceeded the number of allowed tags of 30”

Visual Studio市场不允许扩展包的`package.json`有大于30个`keywords`。限制关键词或标签的数量到30以下以规避此错误。

### 在尝试发布扩展时收到403屏蔽（或401未授权）错误
有个易犯的错误是在创建PAT（个人访问令牌）时在**Organizations**下拉框中选择某个组织而不是**All accessible organizations**。另一个错误是在错误区域中——您应该设置授权区域为`Marketplace(Manage)`以发布。

### 我不能通过vsce工具撤回扩展

您可能变更了扩展ID或发布者ID。您可以直接通过[Visual Studio市场发布者管理页面](https://marketplace.visualstudio.com/manage)管理扩展。例如，上传或[撤回](#撤回扩展)

### 为什么vsce不能保留文件属性
注意在从Windows构建和发布扩展时，所有扩展包体包含的文件回缺失POSIX文件属性，即可执行位元组。一些`node_modules`依赖依靠这些属性正确运行。从Linux和macOS发布如预期运作。

### 我可以从持续集成（CI）构建发布吗

是的，参考[持续集成](4.%20持续集成.md)主体的[自动发布](4.%20持续集成.md#自动发布)小节学习如何配置Azure DevOps、GitHub Actions和GitLab CI自动发布扩展到市场。

### 在尝试发布扩展时收到“ERROR The extension 'name' already exists in the Marketplace”错误
市场需要每个扩展的[扩展名](/9.%20参考/4.%20扩展清单.md)唯一。如果扩展与市场中已经存在的扩展撞名，您就会收到下面错误：

```text
ERROR The extension 'name' already exists in the Marketplace.
```

相同的规则适用扩展的[显示名称](/9.%20参考/4.%20扩展清单.md)

### 什么包管理器受支持
您可以适用npm或yarn v1管理扩展依赖。

### 我在发布扩展时需要VS市场账号的帮助或支持
您可以在[管理发布者与扩展](https://marketplace.visualstudio.com/manage)注册并点击右上方“Contract Microsoft”链接，联系VS市场支持团队。

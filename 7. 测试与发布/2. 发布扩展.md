# 发布扩展

当您完成了一个高质量扩展后，您可以将其发布至[VS Code扩展市场](https://marketplace.visualstudio.com/vscode)，这样其他人就能找到、下载并使用您的扩展。另外，您可以[打包](#打包扩展)为可安装VSIX格式并分享给其他用户。

本主题包含：
- 使用[vsce](#vsce)这个CLI工具管理VS Code扩展
- [打包](#打包扩展)、[发布](#发布扩展)并[撤回](#撤回扩展)扩展
- 必要时[注册发布者](#创建发布者)方便发布扩展

## vsce
[vsce](https://github.com/microsoft/vscode-vsce)，全称Visual Studio Code Extension（Visual Studio Code扩展），是打包、发布、管理VS Code扩展的命令行工具。


### 安装

确保您已经安装了[Node.js](https://nodejs.org/)。并运行：
```bash
npm install -g @vscode/vsce
```

### 用法

您可以使用`vsce`便捷地[打包](#打包扩展)并[发布](#发布扩展)您的扩展：

```bash
$ cd myExtension
$ vsce package
# myExtension.vsix generated
$ vsce publish
# <publisher id>.myExtension published to VS Code Marketplace
```

`vsce`也可以搜索检索元数据，并撤回扩展。运行`vsce --help`查阅所有可用的`vsce`命令。

## 发布扩展
> 注意
> 由于安全问题，`vsce`不会发布包含用户提供SVG图像的扩展。

发布工具检查下面的限制：

- `package.json`提供的图标不应该是SVG。
- `package.json`提供的标志不应该是SVG图像，除非来自[信任的标志提供者](#允许的标志提供者)。
- `README.md`和`CHANGELOG.md`的图像URL应该解析为`https`URL。
- `README.md`和`CHANGELOG.md`的图像不应该是SVG，除非来自[信任的标志提供者](#允许的标志提供者)。

Visual Studio Code使用[Azure DevOps](https://azure.microsoft.com/zh-cn/products/devops/)提供市场服务。这意味着扩展的授权、托管和管理都由Azure DevOps提供。

> 重要事项
> 在2026年12月1日，Azure DevOps全球个人访问令牌（PATs）停用。为了继续发布扩展，使用Microsoft Entra ID代替，以[保证安全自动化发布](#安全自动化发布到Visual Studio Code市场)。想要更多信息，参见[Azure DevOps全球个人令牌停用](https://devblogs.microsoft.com/devops/retirement-of-global-personal-access-tokens-in-azure-devops/)

### 安全自动化发布到Visual Studio Code市场
我们推荐扩展使用[基于Microsoft Entra ID授权](https://learn.microsoft.com/en-us/azure/devops/integrate/get-started/authentication/entra?view=azure-devops)和**工作负载身份联合与托管标识**发布扩展。这个方法消除了消除了如个人访问令牌（PATs）的隐秘，并确保安全、自动化的发布管线。

这个方法通过避免对存储证书的依赖增强了全面安全姿态，通过本地整合Azure管线和Entra ID简化操作，高效跨越多个环境，并适配企业级别的国际认证和访问管理标准。想要更多信息，参见[减少PAT使用](https://devblogs.microsoft.com/devops/reducing-pat-usage-across-azure-devops/)。

1. 创建服务连接（Azure DeveOps）
    - 导航到**Project Settings** → **Service Connections**
    - 创建新的**Azure Resource Manager**连接
    - 选择**Workload Identity Federation (manual)**
    - 在草稿模式下保存连接，之后收集需要的值
2. 创建托管认证（Azure）
    - 在Azure创建**user-assigned managed identity**
    - 指定**Reader**角色
    - 记录下面的值：**Client ID**、**Tenant ID**、**Subscription**详情。
3. 配置联合证书
    建立Azure DevOps和Azure之间的连接：
        - 为托管认证添加联合证书
        - 在两个系统之间交换需要的值：
            - 从Azure DevOps → Azure：**Issuer and subject**
            - 从Azure → Azure DevOps：**client ID, tenant ID, subscription**
        - 在Azure DevOps，选择**Verify and save**
4. 获得管线访问
    - 打开服务连接
    - 获得负责发布的管线访问
5. 检索托管认证资源ID（一次）
    - 运行Azure CLI任务检索认证信息：
```yaml
steps:
- task: AzureCLI@2
  displayName: 'Get identity details'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      az rest -u https://app.vssps.visualstudio.com/_apis/profile/profiles/me --resource 499b84ac-1321-427f-aa17-267ca6975798

```
    - 从输出的JSON，捕获托管认证资源ID（`id`字段）。
6. 授权Visual Studio市场认证
    - 添加托管认证（使用其资源ID）作为发布者的成员
    - 指定**Contributor**角色
7. 配置CI/CD管线
    - 创建Azure管线CI/CD工作流
    - 用基于认证的方式取代基于PAT授权
8. 使用托管认证发布
    - 在您的管线，通过Azure CLI生成Microsoft Entra ID(AAD)访问令牌。 
    - 在您的发布命令中使用令牌（例如：`vsce publish --azure-credential`）。
示例YAML任务。用扩展文件夹路径填入。

```YAML
# 安装VS Code扩展管理器（需要v2.26.1以上的vsce）和依赖
- script: |
    cd <ExtensionDirectory>
    npm install -g @vscode/vsce
    npm install
  displayName: "Install vsce and dependencies"

# 发布
- task: AzureCLI@2
  displayName: 'Publish using managed identity'
  inputs:
    azureSubscription: <ServiceConnectionName>
    scriptType: pscore
    scriptLocation: inlineScript
    inlineScript: |
      cd <ExtensionDirectory>
      vsce publish --azure-credential

```

`vsce`也可以使用[个人访问令牌](https://learn.microsoft.com/zh-cn/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate?view=azure-devops)发布扩展。

> 重要事项
> 在2026年12月1日，Azure DevOps全球个人访问令牌（PATs）停用。为了继续发布扩展，使用Microsoft Entra ID代替，以[保证安全自动化发布](#安全自动化发布到Visual Studio Code市场)。想要更多信息，参见[Azure DevOps全球个人令牌停用](https://devblogs.microsoft.com/devops/retirement-of-global-personal-access-tokens-in-azure-devops/)

### 获得个人访问令牌

您可以通过Azure DevOps门户创建个人访问令牌。如需创建个人访问令牌：

1. 如果您还没有Azure DevOps组织。跟随[创建组织](https://learn.microsoft.com/azure/devops/organizations/accounts/create-organization)一文的步骤。

2. 转到[Azure DevOps门户](https://go.microsoft.com/fwlink/?LinkId=307137)，选择您的组织。

3. 打开档案图像旁的用户设置下拉框，选择**Personal access tokens**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/menu-pat.png)

4. 在**Personal Access Tokens**页面，选择**New Token**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/new-token.png)

5. 在创建新的个人访问令牌对话框，填写下面令牌详情：

    - Name：您为令牌随意取的名称
    - Organization：**All accessible organizations**
    - Expiration（可选）：设置令牌期望的到期时间
    - Scopes：**Custom defined**：
        - 点击**Scopes**段下面的**Show all scopes**链接
        - 在Scopes列表，滑到**Marketplace**选择**Manage**领域

6. 点击**Create**

您就能看到您新创建的个人访问令牌。**拷贝**到安全的位置，随后就需要[创建发布者](#创建发布者)

### 创建发布者

**发布者**是可以发布扩展到Visual Studio Code市场的认证。每个扩展需要在[`package.json`文件](/9.%20参考/4.%20扩展清单.md)包含一个`publisher`标识符。

如需创建发布者：
1. 转到[Visual Studio市场发布者管理页面](https://marketplace.visualstudio.com/manage)。

2. 登录您在之前小节用于创建[个人访问令牌](#获得个人访问令牌)的Microsoft账户。

3. 在左边的面板点击**Create publisher**

4. 在新的页面，指定新发布者的必需参数——标识符和名称（分别为**ID**和**Name**输入框）：
    - **ID**：您在市场中发布者的**唯一**标识符，用在您的扩展URL当中。ID一旦创建不可更改。
    - **Name**：您的发布者的**唯一**名称，将在市场中与扩展一同显示。这可以是您的公司或品牌名称。

下面是Python扩展发布者标识符和名称的例子：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/publisher-id-and-name.png)

5. 可以选择填写剩下的输入框。

6. 点击**Create**

7. 使用`vsce`验证新创建的发布者。在终端中运行下面的命令，有提示词出现时，输入前面步骤创建的个人访问令牌：

```bash
vsce login <publisher id>

https://marketplace.visualstudio.com/manage/publishers/
Personal Access Token for publisher '<publisher id>': ****************************************************

The Personal Access Token verification succeeded for the publisher '<publisher id>'.
```

完成验证后，您可以发布扩展了。

### 发布扩展

您可以用两种方式发布扩展：

1. 使用`vsce publish`命令自动发布扩展：


```bash
vsce publish
```

如果您在上面还没有用`vsce login`命令提供您的个人访问令牌，`vsce`会要求您提供。

2. 使用`vsce package`打包扩展为可安装VSIX格式，随后手动上传到[Visual Studio市场发布者管理页面](https://marketplace.visualstudio.com/manage)

## 查看扩展安装和评分

[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)让您可以随时查看每个扩展的获取趋势、总获取数和评分与评测。如要查看报告，点击扩展或选择**More Actions > Reports**

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/extension-report.png)

## 自动迭代扩展版本
发布完扩展后，您可以指定遵循[语义化版本](https://semver.org/)的数值或版本符号（`major`、`minor`或`patch`）来递增其版本数。例如，要把1.0.0扩展更新为1.1.0，您可以指定：

```bash
vsce publish minor
```
或
```bash
vsce publish 1.1.0
```

两个命令都会首先修改扩展`package.json`[version](/9.%20参考/4.%20扩展清单.md)属性，随后发布更新后的版本。

> 提示
> 如果在git仓库中您运行了`vsce publish`，它也会创建版本提交，并通过[npm-version](https://docs.npmjs.com/cli/version#description)打上标签。默认提交信息为扩展的版本，但您可以使用`-m`标记提供自定义提交消息（在提交消息中可以用`%s`引用当前的版本）。

## 撤回扩展
您可以在[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)撤回扩展，点击**Actions -> Unpublish**：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/unpublish-extension.png)

撤回后，扩展的可用状态更改为**Unpublished**，它将不再可以从市场和Visual Studio Code下载。

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/unpublished-extension.png)

> 注意
> 当您撤回扩展时，市场保留扩展统计。扩展可以被公众找到，并对已有的API可用。

## 移除扩展
您可以用两种方式移除扩展：

1. 使用[`vsce`](#vsce)的`unpublish`命令自动移除：

```bash
vsce unpublish <publisher id>.<extension name>
```

2. 在[Visual Studio发布者管理页面](https://marketplace.visualstudio.com/manage)点击**More Actions > Remove**手动移除：

![](https://code.visualstudio.com/assets/api/working-with-extensions/publishing-extension/remove-extension.png)

两种情况下，会提示您通过输入扩展名称确认移除。注意移除操作是**不可逆的**。

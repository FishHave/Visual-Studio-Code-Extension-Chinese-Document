## 嵌入编程语言

Visual Studio Code提供丰富的编程语言特性。您已经在[语言服务端扩展指南](7.%20语言服务端扩展指南.md)读到，您可以编写语言服务端支持任何编程语言。然而，对于嵌入语言，实现支持要花费更多精力。

此刻，嵌入语言的数量在增长，比如：
- HTML中的JavaScript和CSS
- JavaScript中的JSX
- 模板语言插入，比如Vue， Handlebars和Razor。
- PHP中的HTML

本指南专注实现嵌入语言特性。如果您对提供嵌入语言的词法高亮更感兴趣，可以在[词法高亮指南](2.%20词法高亮指南.md#嵌入语言)找到信息。

本指南包括两个案例，描绘了两种构建语言服务端的方式：**语言服务**和**请求转发**。我们会查看两个示例，并总结各自的优缺点。

两个案例的源代码在：

- [使用语言服务实现嵌入语言语言服务端](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-embedded-language-service)
- [使用请求转发实现嵌入语言语言服务端](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-embedded-request-forwarding)

## 语言服务

**语言服务**是为单种语言实现了[编程式语言特性](6.%20编程式语言特性.md)的库。**语言服务端**可以嵌入语言服务处理嵌入语言。

下面是VS Code HTML支持的框架：

- 内建[html extension](https://github.com/microsoft/vscode/tree/main/extensions/html)仅提供HTML词法高亮和语言配置。
- 内建[html-language-features extenions](https://github.com/microsoft/vscode/tree/main/extensions/html-language-features)包含了HTML语言服务端，为HTML提供其他编程式语言特性。
- HTML语言服务端使用[vscode-html-languageservice](https://github.com/microsoft/vscode-html-languageservice)支持HTML。
- CSS语言服务端使用[vscode-css-languageservice](https://github.com/microsoft/vscode-css-languageservice)以在HTML中支持CSS。

HTML语言服务端分析一份HTML文档，将其分割成语言区域，并使用相关的语言服务处理语言服务端请求。

例如：
- 对于`<|`处的自动补全请求，HTML语言服务端使用HTML语言服务提供HTML补全。
- 对于`<style>.foo { | }</style>`处的自动补全请求，HTML语言服务端使用CSS语言服务提供CSS补全。

让我们测试[lsp-embedded-language-service](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-embedded-language-service)示例，这是HTML语言服务端的简化版本，实现了HTML和CSS的自动补全以及CSS的错误诊断。

### 语言服务端示例

> **注意**：这份示例假定您已经掌握了[编程式语言特性主题](6.%20编程式语言特性.md)和[语言服务端扩展指南](7.%20语言服务端扩展指南.md)。代码会基于[lsp-sample](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-sample)构建。

源代码开发于[microsoft/vscode-extension-samples](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-embedded-language-service)。

相较于[lsp-sample](https://github.com/microsoft/vscode-extension-samples/tree/main/lsp-sample)，客户端代码是一样的。
如同上面所介绍，服务段将文档分割为不同的语言区域以处理嵌入内容。

下面是简单的示例：

```html
<div></div>
<style>.foo { }</style>
```

在这种情况下，服务端检测`<style>`标签，并标记`.foo { }`为CSS区域。

根据某个位置的自动补全请求，服务端使用下面的逻辑计算回复：
- 如果位置属于某个区域
    - 用此区域的语言虚拟文档处理，并把其他区域替换为空格
- 如果位置不属于某个区域
    - 使用HTML的虚拟文档处理，并把其他区域替换为空格

例如：当我们在这个位置触发自动补全：

```html
<div></div>
<style>.foo { | }</style>
```

服务端认为位置处于区域内，并使用下面的内容计算虚拟CSS文档（█代表空格）：
```css
███████████
███████.foo { | }████████
```

服务单随后使用`vscode-css-languageserver`分析文档，计算补全项目列表。因为内容不包含HTML，CSS语言服务处理起来没有任何问题。通过替换非CSS内容为空格，我们拜托了手动调整坐标。

服务端代码处理补全请求：

```typescript
connection.onCompletion(async (textDocumentPosition, token) => {
    const document = documents.get(textDocumentPosition.textDocument.uri);
    if (!document) {
        return null;
    }
    
    const mode = languageModes.getModeAtPosition(document, textDocumentPosition.position);
    if (!mode || !mode.doComplete) {
        return CompletionList.create();
    }
    const doComplete = mode.doComplete!;

    return doComplete(document, textDocumentPosition.position);
});
```

CSS模式负责处理所有属于CSS区域的语言服务端请求：
```typescript
export function getCSSMode(
    cssLanguageService: CSSLanguageService,
    documentRegions: LanguageModelCache<HTMLDocumentRegions>
): LanguageMode {
    return {
        getId() {
            return 'css';
        },
        doComplete(document: TextDocument, position: Position) {
            // 获取虚拟CSS文档，用空格i替换所有非CSS代码
            const embedded = documentRegions.get(document).getEmbeddedDocument('css');
            // 使用vscode-css-languageservice计算回复
            const stylesheet = cssLanguageService.parseStylesheet(embedded);
            return cssLanguageService.doComplete(embedded, position, stylesheet);
        }
    };
}
```

这个方法处理嵌入语言简单有效。然而，也有一些不足：
- 您必须持续更新您的语言服务端依赖的语言服务。
- 如果语言服务和您的语言服务端不使用同种语言编写就会很麻烦。例如，用PHP编写的PHP语言服务端包含使用TypeScript编写的`vscode-css-languageservice`就很复杂。

现在我们有了**请求转发**，能够解决上面的问题。

## 请求转发
简而言之，请求转发和语言服务工作方式类似。请求转发的方式也接受语言服务端请求，演算虚拟文档并计算回复。

主要的不同在于：
- 语言服务的方式使用库计算语言服务端回复，而请求转发发送请求回到VS Code，以使用活跃的扩展，这个扩展已经注册了嵌入语言的补全提供器。

又是下面的简单例子：

```html
<div></div>
<style>.foo { | }</style>
```

自动补全会采用下面的流程：
- 语言客户端使用`workspace.registerTextDocumentContentProvider`为`embedded-content`文档注册虚拟文本文档提供器。
- 语言客户端劫持`<FILE_URI>`的补全请求。
- 语言客户端认为请求位置属于CSS区域。
- 语言客户端构造一个新的URI，比如`embedded-content://css/<FILE_URI/.css`。
- 语言客户端随后调用`commands.executeCommand('vscode.executeCompletionItemProvider', ...)`
    - VS Code的CSS语言服务端回复此提供器请求。
    - 虚拟文本文档提供器根据虚拟文档提供CSS语言服务端，文档中的所有非CSS代码都被替换为了空格。
    - 语言客户端接收来自VS Code的回复，并发送回复。

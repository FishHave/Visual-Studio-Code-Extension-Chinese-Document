# 编写Python扩展

> **注意：**如果您刚开始编写VS Code扩展，可能需要先阅读[您的第一个扩展](/2.%20开始/1.%20您的第一个扩展.md)教程，尝试创建简单的Hello World示例。

[Python](https://marketplace.visualstudio.com/items?itemName=ms-python.python)扩展提供了API给其他扩展操作用户机器上可用的Python环境。查看[@vscode/python-extension](https://www.npmjs.com/package/@vscode/python-extension) npm模块，它包含了类型和助手功能在扩展中访问这些API。

## Python扩展模板
[Python扩展模板](https://github.com/microsoft/vscode-python-tools-extension-template)帮助您开始为您最喜欢的Python工具构建Visual Studio Code扩展。它可能是代码检查工具、格式化器或代码分析，或者以上全部。模板将给予您构建扩展所需要的基本构建代码块，让您整合工具到VS Code中，并且它已经能够访问上面提及的Python API。

## 编程语言和框架

扩展模板有两部分，扩展部分和语言服务端部分。扩展部分是用TypeScript编写，语言服务端部分使用Python的`pygls`（Python语言服务端）库编写。

使用本模板的大部分时间您都在处理Python部分。您将会使用[语言服务端协议](https://microsoft.github.io/language-server-protocol)将工具整合到扩展部分中。`pygls`当前运作在[LSP 3.16版本](https://microsoft.github.io/language-server-protocol/specifications/specification-3-16)

TypeScript部分处理VS Code和其UI。扩展模板携带一些内建设置，可以用在工具中。如果您需要添加新设置支持工具，需要处理一点TypeScript。看木哦站模板有一些设置示例，您也可以看看我们团队为一些热门工具[开发的扩展](#示例)。

## 需求
1. VS Code 1.64.0以上
2. Python 3.7以上
3. node >= 14.19.0
4. npm >= 8.3.0（`npm`和Node安装在一起，检查npm版本，使用`npm install -g npm@8.3.0`更新）
5. VS Code [Python](https://marketplace.visualstudio.com/items?itemName=ms-python.python)扩展

您应该知道如何创建并和Python虚拟环境协作。

## 开始
要开始工作，跟随模板[README](https://github.com/microsoft/vscode-python-tools-extension-template#readme)中的指导。您将从中学习如何使用[模板创建您的仓库](https://docs.github.com/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)，以及如何安装必要工具（例如，[nox](https://nox.thea.codes/)任务运行器）以及可选依赖（测试支持）。

[README](https://github.com/microsoft/vscode-python-tools-extension-template#readme)涵盖最新的指导，也讨论了如何自定义扩展`package.json`占位符的细节（`<pythontool-module>`、`pythontool-display-name`等等）。

## 模板特性
在通过模板创建扩展后，它包含了下面的扩展贡献。假定`<pytool-module>`替换为了`mytool`，`<pytool-display-name>`替换为了`My Tool`：

1. 命令**My Tool: Restart Server**（命令ID:`mytool.restart`）。
2. 下面的设置：
    - `mytool.logLevel`
    - `mytool.args`
    - `mytool.path`
    - `mytool.importStrategy`
    - `mytool.interpreter`
    - `mytool.showNotification`
3. 下面扩展启动触发器：
    - 使用语言`python`。
    - 在打开的工作空间中打开扩展找到的`.py`文件。
    - 使用命令`mytool.restart`。
4. 日志输出通道**输出 > My Tool**。

## 整合您的工具
生成的`bundled/tool/server.py`文件是您做出大部分更改之处。文件中的`TODO`注释指出了不同的自定义处。也可以试试在模板的其他位置搜索`TODO`命令，比如其他Python和Markdown文件。您需要检查LICENSE文件，即便您想要保持为MIT协议。

## 示例

本模板创建了几个示例实现：

- [Pylint](https://github.com/microsoft/vscode-pylint/tree/main/bundled/tool) - 实现代码分析，以及`open`、`save`和`close`的代码操作。
- [Flake8](https://github.com/microsoft/vscode-flake8/tree/main/bundled/tool) - 实现代码分析和代码操作。
- [Black Formatter](https://github.com/microsoft/vscode-black-formatter/tree/main/bundled/tool) - 整合[*Black*](https://github.com/python/black)格式化器。
- [autopep8](https://github.com/microsoft/vscode-autopep8/tree/main/bundled/tool) - 整合[autopep8](https://pypi.org/project/autopep8)格式化器。
- [isort](https://github.com/microsoft/vscode-isort/blob/main/bundled/tool) - 添加排序导入的代码操作。

您也可以查看[语言服务端协议规范](https://microsoft.github.io/language-server-protocol/specifications/specification-3-16)来更好地理解`pygls`语言服务端整合。

## 打包并发布

在发布扩展前，您需要依据扩展情况更新扩展`pacakge.json`字段（比如`publisher`和`license`）。您也需要更新辅助Markdown文件（`CODE_OF_CONDUCT.md`、`CHANGELOG.md`等等）。

一旦扩展预备发布，使用`nox` `build-package`任务创建`.vsix`文件，随后您可以上传到扩展[管理页面](https://marketplace.visualstudio.com/manage)。

如果您是第一次创建和发布VS Code扩展，我们推荐您跟随主VS Code[扩展编写](/7.%20测试与发布/2.%20发布扩展.md#进阶用法)主题所概述的最佳做法。在这您会找到能够帮助您的扩展在市场中看起来更好的指南，以及如何成为认证发布者，以此让用户安心安装您的扩展。

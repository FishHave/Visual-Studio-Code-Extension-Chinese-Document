# 扩展宿主

**扩展宿主**负责运行扩展。

## 扩展宿主配置

基于VS Code的配置，正在运行的扩展宿主可以有多个，并且都具有不同的运行时和不同的位置。

- 本地 - 运行在本地的Node.js扩展宿主，在用户界面相同的机器上。
- 网络 - 运行在浏览器或本地的网络扩展宿主，在用户界面相同的机器上。
- 远程 - 远程运行在容器或远程位置的Node.js扩展宿主。

下面的表格展示了VS Code不同配置下可用的扩展宿主：

| **配置** | **本地扩展宿主** | **网络扩展宿主** | **远程扩展宿主** |
| - | - | - | - |
| 桌面VS Code  | ✔️ | ✔️ | |
| [远程VS Code](https://code.visualstudio.com/docs/remote/remote-overview)（容器、SSH、WSL、GitHub Codespace、Tunnel） | ✔️ | ✔️ | ✔️ |
| VS Code网络版（vscode.dev、github.dev） |  | ✔️ | |
| 具有Codespace的VS Code网络版 | | ✔️ | ✔️ |

### 扩展宿主运行时

- Node.js - 扩展运行在Node.js运行时，用于本地和远程扩展宿主。扩展需要`main`入口文件运行。
- 浏览器 - 扩展运行在[浏览器WebWorker](https://developer.mozilla.org/docs/Web/API/Web_Workers_API)运行时。用于网络扩展宿主。扩展需要`browser`入口文件运行。参考[Web扩展指南](/4.%20扩展指南/13.%20Web扩展.md)获取更多信息。

### 偏好扩展位置
在哪个扩展宿主加载扩展基于：

- VS Code配置给定的可用扩展宿主。
- 扩展能力：它可以在Node.js中运行吗，网络呢，如果没有指定，它贡献了什么？
- 扩展安装在什么地方：在本地机器、远程机器，或者都有。
- 扩展偏好的位置： `extensionKind`属性。

`extensionKind`是[扩展清单](/9.%20参考/4.%20扩展清单.md)的属性。它允许扩展指定偏好的运行位置。可以是持有工作空间（`workspace`）或用户界面（`ui`）的机器。如果扩展可以在两种情况下运行，可以指定偏好顺序。

- `"extensionKind": ["workspace"]` —— 标识扩展需要对工作空间内容的访问权限，因此需要在工作空间处运行。可以是本地机器、远程机器或Codespace。绝大多数扩展在此分类中。
- `"extensionKind": ["ui", "workspace"]` —— 表示扩展**偏好**作为UI扩展运行，但对本地资产、设备或功能没有任何硬性要求。在使用VS Code时，如果扩展宿主存在于本地，意味着用户无需远程安装扩展，扩展将在VS Code本地扩展宿主中运行。否则，扩展会在可用的VS Code工作空间扩展宿主中运行。在使用Codespace上的VS Code网络版时，它永远在远程扩展宿主运行（因为没有可用的本地扩展宿主）。

- `"extensionKind": ["workspace", "ui"]` —— 表示扩展**偏好**作为工作空间扩展运行，但对可访问工作空间内容没有任何硬性要求。在使用VS Code时，如果存在于远程工作空间，扩展将在VS Code工作空间扩展宿主中运行。否则，扩展会在本地可用的VS Code本地扩展宿主中运行。在使用Codespace上的VS Code网络版时，它永远在远程扩展宿主运行（因为没有可用的本地扩展宿主）。
- `"extensionKind": ["ui"]` —— 表明扩展**必须**紧靠UI一同运行，因为它需要对本地资产、设备或功能的访问权限，亦或者需要其他潜在因素的。如果是Codespace上的VS Code网络版，没有本地扩展宿主可用，这样的扩展就不能加载，除非它同时是[Web扩展](/4.%20扩展指南/13.%20Web扩展.md)。随后会在限制的网络扩展宿主中加载，而不能初始化WebWorker。

**注意**：VS Code发布版（< 1.40）允许扩展用字符串指定单个位置，但这已经弃用，更推荐使用数组输入多个位置。

如果扩展可以在Node.js和浏览器中运行，会选择可用的Node.js扩展宿主。有一个例外，当配置为Codespace上的VS Code网络版，并且`extensionKind`设置为`ui`，那么将倾向网络扩展宿主而非远程扩展宿主。

如果扩展仅在网络可用，它永远在网络扩展宿主运行，无论`extensionKind`如何设置。我们推荐不要在这种情况下定义`extensionKind`。

## 稳定性和性能
VS Code目标是为用户提供稳定高性能的编辑器，错误运行的扩展不应该影响用户体验。VS Code扩展宿主阻止扩展：

- 影响启动性能
- 减慢UI操作
- 修改UI
另外，VS Code让扩展声明其[启用事件](/9.%20参考/3.%20启用事件.md)，并惰性加载。例如，Markdown扩展仅应在用户打开Markdown文件下加载。这确保扩展不会消耗不必要的CPU和内存。

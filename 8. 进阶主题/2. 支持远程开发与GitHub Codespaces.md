# 支持远程开发与GitHub Codespaces
[**Visual Studio Code远程开发**](https://code.visualstudio.com/docs/remote/remote-overview)允许您与处于其他机器（无论是虚拟的还是物理的）上的源代码和运行时环境进行完全透明的互动。[**GitHub Codespaces
**](https://github.com/features/codespaces)是一项使用托管云环境扩展这些功能的服务，可以从VS Code和基于浏览器的编辑器访问。

为提高性能，远程开发和GitHub Codespaces都远程透明运行了某些VS Code扩展。然而，这对扩展的工作方式产生了细微的影响。尽管许多扩展不需要修改仍能工作，但是您仍然需要修改扩展使之能够在所有环境下正常运行，虽然这些更改通常很微小。

本文简要介绍了扩展作者需要了解的远程开发和Codespaces内容，包含扩展[结构](#结构与扩展种类)、如何在远程工作空间或Codespaces[调试您的扩展](#调试扩展)，和[如果您的扩展没有正常工作](#常见问题)的建议。

## 结构和扩展种类
为了在远程开发或Codespaces上的运作尽可能对用户透明，VS Code区分两种类型的扩展：

- **UI扩展**：这些扩展贡献VS Code用户界面，永远需要在用户本地机器上运行。UI扩展不可以直接访问远程工作空间的文件或安装在工作空间或机器的运行脚本/工具。示例UI扩展包括：主题、代码片段、语言语法和键盘映射。

- **工作空间扩展**：这些扩展在工作空间位置所处机器运行。如果在本地工作空间，工作空间扩展在本地机器上运行。如果在远程或作空间或使用Codespaces，工作空间扩展在远程机器或环境上运行。工作空间扩展可以访问工作空间的文件提供丰富、多文件语言服务、调试支持或对工作空间的多个文件施展复杂操作（直接或调用脚本/工具）。工作空间扩展尽管不主要修改UI，也可以贡献浏览器、视图和其他UI元素。

在用户安装扩展时，VS Code基于其类型自动安装到正确的位置。如果扩展可以作为任意类型运行，VS Code会尝试选择当前情景最优方案；UI扩展会在VS Code[本地扩展宿主](1.%20扩展宿主.md)运行，而工作空间扩展，如果处在远程工作空间，会在位于小型[**VS Code服务端**](https://code.visualstudio.com/docs/remote/vscode-server)上的**远程扩展宿主**运行，否则如果处在本地则以VS Code本地扩展宿主运行。为确保最新的VS Code服务端特性可用，服务端需要匹配VS Code客户端实际版本。因此，服务端会在容器中、处在远程SSH宿主、使用Codespaces或在Windows Linux子系统（WSL）中打开文件夹、时由远程开发或GitHub Codespaces扩展自动安装（或更新）。（VS Code也能自动管理服务端的启动和停止，所以用户不会意识到其存在。）

![](https://code.visualstudio.com/assets/api/advanced-topics/remote-extensions/architecture.png)

VS Code API设计好在被UI或工作空间调用时自动运行在正确的机器（本地或远程）。然而，如果您的扩展使用不由VS Code提供的API——比如使用Node API运行命令行解释器脚本——它可能在远程不会正确运行。我们推荐您在本地和远程工作空间测试扩展所有特性的正确运行。

## 调试扩展
您在远程环境[可以安装您的扩展的开发版本](#安装您的扩展的开发版本)用于测试，如果您遇到了问题，可能希望直接在远程环境下调试扩展。在本节，我们会涵盖如何在[GitHub Codespaces](#在GitHub Codespaces调试)、[本地容器](#在本地容器调试)、[SSH宿主](#在SSH宿主调试)或[WSL](#在WSL调试)上编辑、启动和调试扩展。

通常来说，调试的最好起点是使用限制端口访问的远程环境（例如Codespaces、容器或带有防火墙的远程SSH宿主），因为运行在这些环境的扩展会较如WSL等限制较少的环境下更容易工作。

### 在GitHub Codespaces调试
在[GitHub Codespaces](https://docs.github.com/github/developing-online-with-codespaces)预览版调试扩展会是很好的出发点，因为您可以使用VS Code和Codespaces基于浏览器的编辑器调试和除错。如果喜欢可以使用[自定义开发容器](#在自定义开发容器调试)。

跟随下面的步骤：

1. 导航到GitHub上的扩展仓库，并[在Codespace中打开](https://docs.github.com/github/developing-online-with-codespaces/creating-a-codespace)以在基于浏览器的编辑器中处理。如果喜欢可以[在VS Code中打开Codespace](https://docs.github.com/github/developing-online-with-codespaces/using-codespaces-in-visual-studio-code)。

2. 对GitHub Codespaces的默认印象可能是已经对大部分扩展有了需要的前置，但您可以在新的VS Code终端窗口（<kbd>Ctrl+Shift+`</kbd>）安装任何其他需要的依赖（例如，使用`yarn install`或`sudo apt-get`）。

3. 最后，按下<kbd>F5</kbd>或使用**运行和调试**视图在Codespace中启动扩展。

> **注意：**您不可以在出现的窗口打开扩展源代码，但您可以打开子文件夹或Codespace的其他地方。

出现的扩展开发宿主窗口将包含Codespace中运行的扩展，并附着了调试器。

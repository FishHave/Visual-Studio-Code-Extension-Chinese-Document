# 支持远程开发与GitHub Codespaces
[**Visual Studio Code远程开发**](https://code.visualstudio.com/docs/remote/remote-overview)允许您与处于其他机器（无论是虚拟的还是物理的）上的源代码和运行时环境进行完全透明的互动。[**GitHub Codespaces
**](https://github.com/features/codespaces)是一项使用托管云环境扩展这些功能的服务，可以从VS Code和基于浏览器的编辑器访问。

为提高性能，远程开发和GitHub Codespaces都远程透明运行了某些VS Code扩展。然而，这对扩展的工作方式产生了细微的影响。尽管许多扩展不需要修改仍能工作，但是您仍然需要修改扩展使之能够在所有环境下正常运行，虽然这些更改通常很微小。

本文简要介绍了扩展作者需要了解的远程开发和Codespaces内容，包含扩展[结构](#结构与扩展种类)、如何在远程工作空间或Codespaces[调试您的扩展](#调试扩展)，和[如果您的扩展没有正常工作](#常见问题)的建议。

## 结构和扩展种类
为了在远程开发或Codespaces上的运作尽可能对用户透明，VS Code区分两种类型的扩展：

- **UI扩展**：这些扩展贡献VS Code用户界面，永远需要在用户本地机器上运行。UI扩展不可以直接访问远程工作空间的文件或安装在工作空间或机器的运行脚本/工具。示例UI扩展包括：主题、代码片段、语言语法和键盘映射。

- **工作空间扩展**：这些扩展在工作空间位置所处机器运行。如果在本地工作空间，工作空间扩展在本地机器上运行。如果在远程或作空间或使用Codespaces，工作空间扩展在远程机器或环境上运行。工作空间扩展可以访问工作空间的文件提供丰富、多文件语言服务、调试支持或对工作空间的多个文件施展复杂操作（直接或调用脚本/工具）。工作空间扩展尽管不主要修改UI，也可以贡献浏览器、视图和其他UI元素。

在用户安装扩展时，VS Code基于其类型自动安装到正确的位置。如果扩展可以作为任意类型运行，VS Code会尝试选择当前情景最优方案；UI扩展会在VS Code[本地扩展宿主](1.%20扩展宿主.md)运行，而工作空间扩展，如果处在远程工作空间，会在位于小型[**VS Code服务端**](https://code.visualstudio.com/docs/remote/vscode-server)上的**远程扩展宿主**运行，否则如果处在本地则以VS Code本地扩展宿主运行。为确保最新的VS Code服务端特性可用，服务端需要匹配VS Code客户端实际版本。因此，服务端会在容器中、处在远程SSH宿主、使用Codespaces或在Windows Linux子系统（WSL）中打开文件夹、时由远程开发或GitHub Codespaces扩展自动安装（或更新）。（VS Code也能自动管理服务端的启动和停止，所以用户不会意识到其存在。）

![](https://code.visualstudio.com/assets/api/advanced-topics/remote-extensions/architecture.png)

VS Code API设计好在被UI或工作空间调用时自动运行在正确的机器（本地或远程）。然而，如果您的扩展使用不由VS Code提供的API——比如使用Node API运行命令行解释器脚本——它可能在远程不会正确运行。我们推荐您在本地和远程工作空间测试扩展所有特性的正确运行。

## 调试扩展
您在远程环境[可以安装您的扩展的开发版本](#安装您的扩展的开发版本)用于测试，如果您遇到了问题，可能希望直接在远程环境下调试扩展。在本节，我们会涵盖如何在[GitHub Codespaces](#在GitHub Codespaces调试)、[本地容器](#在本地容器调试)、[SSH宿主](#在SSH宿主调试)或[WSL](#在WSL调试)上编辑、启动和调试扩展。

通常来说，调试的最好起点是使用限制端口访问的远程环境（例如Codespaces、容器或带有防火墙的远程SSH宿主），因为运行在这些环境的扩展会较如WSL等限制较少的环境下更容易工作。

### 在GitHub Codespaces调试
在[GitHub Codespaces](https://docs.github.com/github/developing-online-with-codespaces)预览版调试扩展会是很好的出发点，因为您可以使用VS Code和Codespaces基于浏览器的编辑器调试和除错。如果喜欢可以使用[自定义开发容器](#在自定义开发容器调试)。

跟随下面的步骤：

1. 导航到GitHub上的扩展仓库，并[在Codespace中打开](https://docs.github.com/github/developing-online-with-codespaces/creating-a-codespace)以在基于浏览器的编辑器中处理。如果喜欢可以[在VS Code中打开Codespace](https://docs.github.com/github/developing-online-with-codespaces/using-codespaces-in-visual-studio-code)。

2. 对GitHub Codespaces的默认印象可能是已经对大部分扩展有了需要的前置，但您可以在新的VS Code终端窗口（<kbd>Ctrl+Shift+`</kbd>）安装任何其他需要的依赖（例如，使用`yarn install`或`sudo apt-get`）。

3. 最后，按下<kbd>F5</kbd>或使用**运行和调试**视图在Codespace中启动扩展。

> **注意：**您不可以在出现的窗口打开扩展源代码，但您可以打开子文件夹或Codespace的其他地方。

出现的扩展开发宿主窗口将包含Codespace中运行的扩展，并附着了调试器。

### 在自定义开发容器调试

跟随下面步骤：
1. 要在本地使用开发容器，[安装并配置安装容器扩展](https://code.visualstudio.com/docs/devcontainers/containers#getting-started)，然后使用**文件 > 打开... / 打开文件夹...**来在本地VS Code中打开源代码。如果改用Codespace，导航到GitHub上的扩展仓库，并[在codespace中打开](https://docs.github.com/github/developing-online-with-codespaces/creating-a-codespace)以在基于浏览器的编辑器中处理。如果喜欢，也可以[在VS Code中打开codespace](https://docs.github.com/github/developing-online-with-codespaces/using-codespaces-in-visual-studio-code)

2. 从命令面板（<kbd>F1</kbd>）选择**Dev Containers: Add Dev Container Configuration Files...**或者**Configuration Files...**，选择**Node.js & TypeScript**（如果您不使用TypeScript，选择Node.js）添加需要的容器配置文件。

3. **可选：**在运行命令后，修改`.devcontainer`文件夹的内容以包含额外的构建或运行时需求。参见深入的[创建开发容器](https://code.visualstudio.com/docs/devcontainers/create-dev-container)获取细节。

4. 运行**Dev Containers: Reopen in Container**或**Codespaces: Add Dev Container Configuration Files...**，一会之后，VS Code将启动并连接容器。您现在可以在容器内部开发源代码，就如同在本地中一样。

5. 在新的VS Code终端窗口（<kbd>Ctrl+Shift+`</kbd>）运行`yarn install`或`npm install`确保Node.js Linux版本的本地依赖已经安装。您也可以安装其他OS或运行时依赖，但如果您重新构建容器，也许会需要添加这些内容到`.devcontainer/Dockerfile`以启用。

6. 最后，按下<kbd>F5</kbd>或使用**运行和调试**视图在相同的容器内部启动扩展，并附着调试器。

> **注意：**您可能无法在出现的窗口打开扩展源代码，但您可以打开子文件夹或容器其他地方。

出现的扩展开发宿主窗口将包含容器中运行的扩展，并附着了调试器。

### 使用SSH调试

跟随步骤：
1. 在[安装并配置远程 - SSH扩展](https://code.visualstudio.com/docs/remote/ssh#getting-started)之后，从VS Code命令面板（<kbd>F1</kbd>）选择**Remote-SSH: Connect to Host...**来连接宿主。

2. 完成连接后，使用**文件 > 打开... / 打开文件夹...**选择带有您的扩展源代码的远程文件夹或在命令面板（<kbd>F1</kbd>）中选择**Git: Clone**来克隆并在远程宿主中打开。

3. 在新的VS Code终端窗口（<kbd>Ctrl+Shift+`</kbd>）安装所有可能确实的必需依赖（例如使用`yarn install`或`apt-get`）。

4. 最后，按下<kbd>F5</kbd>或使用**运行和调试**视图在远程宿主启动扩展，并附着调试器。

> **注意：**您可能无法在出现的窗口打开扩展源代码，但您可以打开子文件夹或SSH宿主其他地方。

出现的扩展开发宿主窗口将包含SSH宿主中运行的扩展，并附着了调试器。

### 使用WSL调试

跟随下面步骤：

1. 在[安装并配置WSL扩展之后](https://code.visualstudio.com/docs/remote/wsl)，从VS Code命令面板（<kbd>F1</kbd>）选择**WSL: New Window**。

2. 在新出现的窗口，使用**文件 > 打开... / 打开文件夹...**选择带有您的扩展源代码的远程文件夹或在命令面板（<kbd>F1</kbd>）中选择**Git: Clone**来拷贝并在WSL中打开。

> **提示：**您可以选择`/mnt/c`文件夹来访问Windows端拥有的文件夹拷贝。

3. 在新的VS Code终端窗口（<kbd>Ctrl+Shift+`</kbd>）安装所有可能确实的必需依赖（例如使用`yarn install`或`apt-get`）。

4. 最后，按下<kbd>F5</kbd>或使用**运行和调试**视图启动扩展，并像在本地一样附着调试器。

> **注意：**您可能无法在出现的窗口打开扩展源代码，但您可以打开子文件夹或WSL其他地方。

出现的扩展开发宿主窗口将包含WSL中运行的扩展，并附着了调试器。

## 安装扩展的开发版本

无论何时VS Code自动在SSH宿主、容器中或WSL或GitHub Codespaces安装扩展，都将使用市场版本（而不是已经安装在本地机器的版本）。

尽管大多数情况下这是合理的，然而您可能想要使用（或分享）您的扩展用于测试未发布版本，而不需要启动调试环境。为了安装您的扩展的未发布版本，可以打包扩展为`VSIX`，并手动在连接到运行中远程环境的VS Code窗口中安装。

跟随下面步骤：

1. 如果这是一个已发布的扩展，在`settings.json`中添加`"extension.autoUpdate": false`避免自动更新为最新市场版本。

2. 下一步，使用`vsce package`打包您的扩展为VSIX。

3. 连接到[codespace](https://docs.github.com/github/developing-online-with-codespaces)、[开发容器](https://code.visualstudio.com/docs/devcontainers/containers)、[SSH宿主](https://code.visualstudio.com/docs/remote/ssh)或[WSL环境](https://code.visualstudio.com/docs/remote/wsl)。

4. 使用扩展视图**更多操作**（`...`）菜单中**从VSIX安装...**命令安装扩展到这个窗口（而不是本地窗口）。

5. 提示时重新加载。

> **提示**：安装完成后，您可以使用**开发者：显示运行中的扩展**命令查看VS Code在本地还是远程运行扩展。

## 处理远程扩展依赖

扩展可以基于其他扩展的API。比如：

- 扩展可以从`activate`函数导出API
- 此API会对所有运行在相同扩展宿主的扩展可用。
- 消费者扩展在其`package.json`中使用`extensionDependencies`属性声明其基于提供者扩展。

扩展依赖在所有扩展本地运行时良好运作，共享相同的扩展宿主。

面对远程场景，远程运行的扩展可能依赖本地运行的扩展。例如，本地扩展暴露的一个对远程扩展功能来说必需的命令。在此情况下，我们建议远程扩展将本地扩展声明为`extensionDependency`，但问题在于扩展运行在两个不同的扩展宿主，这意味着来自提供者的API对消费者并不可用。因此需要提供者扩展在`package.json`中使用`"api": "none"`放弃导出任何API的功能。扩展仍然可以通过VS Code命令交流（异步）。

这在提供者扩展也许是不必要的严苛限制，但使用`"api": "none"`的扩展仅仅放弃了从`activate`方法返回API的能力。执行在其他扩展宿主的消费者扩展仍然可以依赖并启用。

## 常见问题

VS Code API设计于自动运行在正确的位置，无论您的扩展定位在哪里。记住这条规则后，有一些API可以帮助您避免非期望的行为。

### 不正确的执行位置

如果您的扩展没有按预期运行，它可能运行在错误的位置。最常见的情况，在您希望它只在本地运行时显示运行在远程。您可以从命令面板（<kbd></kbd>）使用**开发者：显示运行中的扩展**命令查看扩展运行的位置。

如果**开发者：显示运行中的扩展**命令显示UI扩展错误地被当做工作空间扩展，或者反过来，如同在[扩展类型小节](/8.%20进阶主题/1.%20扩展宿主.md#偏好扩展位置)所介绍，尝试在扩展[package.json](/2.%20开始/2.%20扩展解剖.md#扩展清单)中设置`extensionKind`属性。

您可以使用`remote.extensionKind`[设置](https://code.visualstudio.com/docs/configure/settings)快速**测试**更改扩展类型的效果。这个设置是扩展ID到扩展种类的映射。例如，如果您想要强制将[Azure Databases](https://marketplace.visualstudio.com/items?itemName=ms-azuretools.vscode-cosmosdb)扩展改为UI扩展（而不是默认的工作空间扩展），或让[Remote - SSH: Editing Configuration Files](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh-edit)扩展改为工作空间扩展（而不是默认的UI），可以设置：

```json
{
    "remote.extensionKind": {
        "ms-azuretools.vscode-cosmosdb": ["ui"],
        "ms-vscode-remote.remote-ssh-edit": ["workspace"]
    }
}
```

使用`remote.extensionKind`让您得以快速测试扩展的发布版本，而不是修改其`package.json`并构建。

## 保存扩展数据或状态
在某些情况，您的扩展需要保存不属于`settings.json`或独立工作空间配置文件（例如`.eslintrc`）的状态信息。为解决此问题，VS Code在启用时传递给扩展的`vscode.ExtensionContext`对象提供了一系列有用的存储属性。如果您的扩展已经利用了这些属性，无论在什么地方运行，都应该继续正常运作。

然而，如果您的扩展基于当前VS Code路径规范（例如：`~/.vscode`）或某个OS文件夹（例如Linux的`~/.config/Code`）来保存数据，可能会遭遇问题。幸运的是，更新扩展避免这些麻烦很简单。

如果您保存单个键值对，可以分别使用`vscode.ExtensionContext.workspaceState`或`vscode.ExtensionContext.globalState`针对工作空间或全局状态信息存储。如果您的数据比键值对更复杂，`globalStorageUri`和`storageUri`属性提供了更“安全”的URI，您可以用来在一个文件中读写针对全局工作空间的信息。

要使用API：

```typescript
import * as vscode from 'vscode';

export function activate(context: vscode.ExtensionContext) {
    context.subscriptions.push(
        vscode.commands.registerCommand('myAmazingExtension.persistWorkspaceData', async () => {
            if (!context.storageUri) {
                return;
            }

            // 如果扩展工作空间存储文件夹不存在，创建之
            try {
                // 如果文件夹不存在，抛出错误
                await vscode.workspace.fs.stat(context.storageUri);
            } catch {
                // 创建扩展工作空间存储文件夹
                await vscode.workspace.fs.createDirectory(context.storageUri)
            }
            
            const workspaceData = vscode.Uri.joinPath(context.storageUri, 'workspace-data.json');
            const writeData = new TextEncoder().encode(JSON.stringify({ now: Data.now() }));
            vscode.workspace.fs.writeFile(workspaceData, writeData);
        }
    ));

    context.subscriptions.push(
        vscode.commands.registerCommand('myAmazingExtension.persistGlobalData', async () => {
        
        if (!context.globalStorageUri) {
            return;
        }

        // 如果扩展全局（跨工作空间）文件夹不存在，创建之
        try {
            //当文件夹不存在时，抛出错误
            await vscode.workspace.fs.stat(context.globalStorageUri);
        } catch {
            await vscode.workspace.fs.createDirectory(context.globalStorageUri)
        }

        const workspaceData = vscode.Uri.joinPath(context.globalStorageUri, 'global-data.json');
        const writeData = new TextEncoder().encode(JSON.stringify({ now: Data.now() }));
        vscode.workspace.fs.writeFile(workspaceData, writeData);
        }
    ));
}
```

### 在机器间同步用户全局状态

如果扩展需要在不同机器间保留一些用户数据，使用`vscode.ExtensionContext.globalState.setKeysForSync`提供状态给[设置同步](https://code.visualstudio.com/docs/configure/settings-sync)。这有助于避免在多个机器显示相同的欢迎或更新页面给用户。

在[扩展功能](/3.%20扩展功能/2.%20通用功能.md#数据存储)主题有使用`setKeysforSync`的示例。

## 保存私密内容

如果扩展需要保存口令或其他秘密，您也许需要使用Visual Studio Code [SecretStorage API](/9.%20参考/1.%20VS%20Code%20API.md)，它提供了基于加密在文件系统上安全存储文本的方式。例如，在桌面，我们使用Electron的[safeStorage API](https://www.electronjs.org/docs/latest/api/safe-storage)在存储到文件系统前加密。API一直将私密内容存放在客户端，但无论您的扩展运行，你可以使用此API，并检索相同的私密内容值。

> **注意**：此API是推荐的保存密码与私密内容的方式。您**不**应该使用`vscode.ExtensionContext.workspaceState`或`vscode.ExtensionContext.globalState`存储私密内容，因为这些API使用普通文本存储数据。

下面是示例：

```typescript
import * as vscode from 'vscode';

export function activate(context: vscode.ExtensionContext) {
    // ...
    const myApiKey = context.secrets.get('apiKey');
    // ...
    context.secrets.delete('apiKey');
    // ...
    context.secrets.store('apiKey', myApiKey);
}
```

### 使用剪切板
扩展作者曾经使用Node.js模块，比如`clipboardy`与剪切板交互。不幸的是，如果您在工作空间扩展使用这些模块，他们会使用远程剪切板而不是用户本地剪切板。VS Code剪切板API解决了这个问题。它永远在本地运行，无论调用它的扩展类型。

要在扩展中使用VS Code剪切板API：

```typescript
import * as vscode from 'vscode';

export function activate(context: vscode.ExtensionContext) {
    context.subscriptions.push(
        vscode.commands.registerCommand('myAmazingExtension.clipboardIt', async () => {
            // 从剪切板读取
            const text = await vscode.env.clipboard.readText();

            // 写入剪切板
            await vscode.env.clipboard.writeText(
                `It loots like you're copying "${text}". Would you like help?`
            );
        })
    );
}
```

### 在本地浏览器或应用程序打开某些东西
生成进程或使用`opn`等模块启动浏览器或其他应用程序使用某个URI可以在本地场景起到效果，但是工作空间扩展在本地运行，导致应用程序在错误的端启动。VS Code远程开发**部分**兼容了`opn` Node模块允许现有的扩展实现功能。您可以用URI调用模块，VS Code会让默认URI调用的应用程序出现在客户端。然而，这并非完整实现，不支持选项，且不返回`child_process`对象。

与其依赖第三方Node模块，我们建议扩展利用`vscode.env.openExternal`方法在本地操作系统为给定URI启动默认注册应用程序。甚至`vscode.env.openExternal`**能够自动传递本地主机端口**！您可以使用它指向远程机器或codespace的本地Web服务器，在端口被外部阻塞时提供内容。

    > **提示**：当前Codespace基于浏览器的编辑器的传递机制仅支持**http和https**
    > **请求**。然而，在从VS Code连接到codespace时，您可以与任何TCP连接交互。

要使用`vscode.env.openExternal`API：

```typescript
import * as vscode from 'vscode';

export async function activate(context: vscode.ExtensionContext) {
    context.subscriptions.push(
        vscode.commands.registerCommand('myAmazingExtension.openExternal', () => {
            // 示例1 - 在默认浏览器中打开VS Code主页。
            vscode.env.openExternal(vscode.Uri.parse('https://code.visualstudio.com'));

            // 示例2 - 打开自动传递本地主机HTTP服务器。
            vscode.env.openExternal(vscode.Uri.parse('http://localhost:3000'));

            // 示例3 - 打开默认邮件应用。
            vscode.env.openExternal(vscode.Uri.parse('mailto:<fill in your email here>'));
            
        })
    )
}
```
